# 作業依頼: AI Software Factory 初回の現状調査

- 根拠となる標準: [AI Software Factory Engineering Standard](../../standards/ai-software-factory-engineering-standard.md)
- 状態: 未着手

標準を受け取ったClaude Codeには、以下の対応を求める。

## 1. 現状調査

リポジトリを調査し、以下を確認する。

- CLAUDE.md・Rules・Skills・Hooksの構成
- アーキテクチャと設計ドキュメント
- Issue・PRの運用
- 開発ワークフロー
- テスト・CI/CD・セキュリティ設定
- エージェントの権限と実行環境
- コンテキスト・知識管理
- 実行履歴・コスト計測
- 継続的改善の仕組み

## 2. ギャップ分析

標準の第2章の10要素について、以下を整理する。

| 項目 | 内容 |
|---|---|
| 現状 | 実際に確認できた構成 |
| 評価 | 充足・部分充足・未充足・未確認 |
| 問題点 | 不足している要素やリスク |
| 改善案 | 具体的な対応方法 |
| 優先度 | 必須・推奨・将来対応 |
| 影響範囲 | 変更対象のファイル・設定 |
| 根拠 | 標準・公式資料への参照 |

現状を確認できない場合は「未確認」とし、推測で導入済みと判断しないこと。

## 3. 提出成果物

1. 現状調査レポート
2. 10要素のギャップ分析
3. 優先順位付き改善バックログ
4. 推奨リポジトリ構成
5. CLAUDE.md・Rules・Hooksの改善案
6. テスト・CI/CD・セキュリティ基盤の改善案
7. AI Software Factoryへの移行ロードマップ
8. Skills・Plugins・開発ワークフローの比較PoC計画

## 4. 実施上の制約

- 初回は調査・分析・提案を優先する。
- 無断で大規模な変更を行わない。
- 標準の構成を機械的に強制しない。
- 既存の適切な設計を尊重する。
- 同じ役割を持つツールの重複導入を避ける。
- セキュリティ設定を緩和しない。
- 本番環境へ直接変更を加えない。
- 公式資料の事実と独自提案を区別する。
- 導入効果・費用・保守負担を評価する。
