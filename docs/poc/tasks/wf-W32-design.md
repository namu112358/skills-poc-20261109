# W32 の設計: 確かめた結果を書かせると、目にしたエラーを指摘に入れるか

- 作成: 2026-11-11（試行の前に固定）
- 依頼: ユーザー「結果から学習して新しい PoC をやっておいて」。W28・W31 の結果から、コーディネーターが代理人の原則（`docs/poc/proxy/principles.md`）で設計した。判断の記録は `docs/poc/results/workflow/W32/decisions.md`。

## 1. 何を確かめるか

- W28 と W31 で、本番で起動して開いた画面で 500 やエラーを目にしたのに、指摘に書かなかった試行があった（W28 で 1 本、W31 で 1 本）。
- W32 は、W28 の依頼文に「開いた画面・呼んだ API ごとに、状態コードとエラーの表示があったかを確かめた結果として書き、エラーが出たものは原因が分からなくてもそれ自体を指摘する」を足すと、本番でだけ出る不具合（W20 c2 B1）を見つける回数が増えるかを確かめる。

## 2. 評価セット・設定・本数

- 題材: W20 の実際の題材。狙いの c2 を 4 回、c3・c4 を 1 回ずつ（6 本）。正解は W20 のまま。
- 設定: `baseline-e2e-report`（Sonnet）。比べる相手は W28（`baseline-e2e`）。手順・許可リストは W28 と同じ。判定は W20 と同じ基準・同じ判定役。
