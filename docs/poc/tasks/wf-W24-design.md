# W24 の設計: 見つけにくい問題を仕込んだ UI レビュー

- 作成: 2026-11-11（W23 の後、試行の前に固定）
- 依頼者の指示（検証結果から新たな PoC を検討して進める）を受けて、コーディネーターが W21 の UI レビュー（W21c）の結果から立てた。
- 試行の仕組み・判定は W21c と同じ（[wf-W21-design.md](wf-W21-design.md) の W21c）。課題名は `W21g`、試行 ID は `W21g-<構成>-<回>`。

## 1. きっかけ

W21c では、どの構成（ツールなしを含む）も仕込んだ 9 件の問題をすべて見つけた。問題が、ラベルの欠落・コントラスト不足・横スクロールのような、コードを読めば分かるものだったため。レビューの道具に差が出るのは、もっと見つけにくい問題のはずなので、確かめ直す。

## 2. 問い

1. コードを読むだけでは見落としやすい UI の問題（キーボード操作の順番、フォーカスの行方、動きを減らす設定、状態の取り違え、成功の伝え方）を、レビューの道具を使うと多く見つけられるか。
2. 道具は、Web Design Guidelines と Impeccable の `audit`・`critique` のどちらが良いか。
3. 4 つすべてを入れた今の標準ではどうか。

## 3. 題材

- 差分: W6 の参照実装の「マイタスク」画面に、問題 8 件とおとり 5 件を仕込んだもの（`docs/poc/answer-key/W21/review-g.patch`、正解は `truth-g.md`）。
- 依頼文: W21c と同じ（[wf-W21g.md](wf-W21g.md)。PR の説明も同じ）。

## 4. 比べる構成

| 構成 | 道具 | `CLAUDE.md` に足す指示 |
|---|---|---|
| `ui-none` | なし | なし |
| `ui-all` | 4 つすべて | なし（今の標準） |
| `ui-wdg-rv` | Frontend Design + Web Design Guidelines | 作るときは `frontend-design`、レビューするときは `web-design-guidelines` を使う（W22 の提案の標準に、レビューの指示を足したもの） |
| `ui-a-rv` | Impeccable + Web Design Guidelines | 作るときは `impeccable`、レビューするときは `impeccable` の `audit` と `critique` を使う |

指示の文面は `docs/poc/tasks/wf-W24-<構成>.md`（固定）。4 構成 × 3 回 = 12 本。

## 5. 測るもの

W21c と同じ。判定役（`claude-opus-5-5`）が指摘を正解（B1〜B8）・おとり（D1〜D5）・正解外に振り分ける。品質 = 見つけた割合 × 80 + 20 −（おとりと誤りへの指摘 1 件につき 5）。指定した Skill が呼ばれたかと、費用も見る。

判定: ある道具の構成が、ツールなしより平均で 2 件以上多く見つけ、誤った指摘が増えなければ、その道具でのレビューを標準の手順に入れる候補にする。
