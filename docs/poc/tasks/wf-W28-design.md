# W28 の設計: 本番で起動して確かめると、本番でだけ出る不具合を見つけられるか

- 作成: 2026-11-11（試行の前に固定）
- 依頼: ユーザー「結果から学習して新しい PoC をやっておいて」。W27 の結果から、コーディネーターが代理人の原則（`docs/poc/proxy/principles.md`）で設計した。判断の記録は `docs/poc/results/workflow/W28/decisions.md`。

## 1. 何を確かめるか

- W20 の 35 本・W27 の 12 本のレビューは、どれも「本番で詳細の画面が 500」（W20 c2 の B1。サーバーの部品からクライアントの部品へ DB の行をそのまま渡すと、本番の起動でだけ落ちる）を見つけなかった。W27 では、関数を呼ぶ再現は行っていたが、本番ビルドして起動し画面を開いた試行は 1 本も無かった（起動と Playwright MCP は W6 以降ずっと許可している）。
- W28 は、レビューの依頼に「本番ビルドして起動し、ログインして、変更された画面・API を実際に開いて確かめてから指摘する」を足すと、この不具合を見つけられるか、費用と時間はどれだけ増えるかを確かめる。

## 2. 評価セット・設定・本数

- 題材: W20 の実際の題材 c2（本番でだけ出る不具合を含む）・c3・c4（比べるため）。正解は W20 のまま。
- 設定: `baseline-e2e`（Sonnet）。依頼文は道具なし + 上の指示。比べる相手は W27 の Sonnet（指示なし・関数を動かす指示）。
- 本数: c2 を 3 回、c3・c4 を 2 回ずつ（7 本）。手順・許可リストは W27 と同じ（`npm run build`・`npm run start`・Playwright MCP・`curl -s` を含む）。試行の後、子セッションが起動したサーバーは `run-trial.sh` が止める。
- 判定: W20 と同じ基準・同じ判定役。
