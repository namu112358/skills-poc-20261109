
## 開発規約（チームの決まり）

- スキーマの変更は `src/lib/db/migrations.ts` の末尾に新しいマイグレーションを足して行い、既存のマイグレーションは書き換えない。本番のデータが残ることを前提にする。
- 列や表の置き換えは段階を分ける（新しいものを足す → 両方に書く → 既存のデータを埋める → 読む側を切り替える → 古いものは後のリリースで消す）。前の版のアプリに戻しても動く状態を保つ。
- 大量のデータを書き換える処理は、件数を区切って短いトランザクションで行い、起動やほかの書き込みを長く止めない。
- 外部の利用者（ハンディ端末・ほかの部署の集計など）が使っている API・列の形は、相手が切り替えるまで変えない。
- 依頼に書かれていない仮定を置いたら、コミットメッセージ（PR があれば PR の説明）に書く。移行の手順と戻し方は `docs/` に書く。
