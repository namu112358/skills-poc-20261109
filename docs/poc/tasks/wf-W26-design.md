# W26 の設計: 「動かして確かめる」を CLAUDE.md の規約に置いても効くか

- 作成: 2026-11-11（試行の前に固定）
- 依頼: ユーザー「結果から学習して新しい PoC をやっておいて」。W24・W25 の結果から、コーディネーターが代理人の原則（`docs/poc/proxy/principles.md`）で設計した。判断の記録は `docs/poc/results/workflow/W26/decisions.md`。

## 1. 何を確かめるか

- W24 では、「疑わしい所は小さな再現スクリプトで実際に動かして確かめてから指摘する」を**レビューの依頼文**に足すと、Sonnet の見落としが減った（日曜の不具合 0/6 → 6/6）。W25 では、ほかの種類の題材で悪さをしないことを確かめた。
- 標準として配るときは、毎回の依頼文ではなく、**プロジェクトの `CLAUDE.md`（雛形の `AGENTS.md` の規約）に常に書いておく**形になる。W26 は、その置き方でも同じ効果が出るかを確かめる。

## 2. 評価セット・設定・本数

- 題材: W24 と同じ c4・d1・d3（`docs/poc/answer-key/W24/cases/`）。
- 設定: `baseline-std`（Sonnet）。レビューの依頼文は W21〜W24 の道具なしと同じ。作業用コピーのアプリの `CLAUDE.md` の末尾に「## レビューの規約」として、W24 の指示と同じ内容の一文を足す（初期状態の一部なので、レビュー対象の差分には出ない）。
- 比べる相手: W24 の Sonnet 指示なし（`baseline`）と、依頼文に指示を足した Sonnet（`baseline-run`）。
- 本数: 3 題材 × 3 回 = 9 本。判定・手順・許可リストは W24 と同じ。
