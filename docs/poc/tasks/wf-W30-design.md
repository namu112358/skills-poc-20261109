# W30 の設計: 要件を照らす指示と、本番で起動して確かめる指示を合わせる

- 作成: 2026-11-11（試行の前に固定）
- 依頼: ユーザー「結果から学習して新しい PoC をやっておいて」。W28・W29 の結果から、コーディネーターが代理人の原則（`docs/poc/proxy/principles.md`）で設計した。判断の記録は `docs/poc/results/workflow/W30/decisions.md`。

## 1. 何を確かめるか

- W28（本番で起動して確かめる）は本番でだけ出る不具合（W20 c2 B1）を見つけ、W29（要件を 1 つずつ照らす）は要件違反（W20 c3 B2）を見つけた。お互いが落としたものを、もう一方が見つけている。
- W30 は、2 つの指示を 1 つの依頼文に合わせたとき、両方の不具合を同時に見つけられるか、費用と時間はどれだけ増えるかを確かめる。

## 2. 評価セット・設定・本数

- 題材: W20 の実際の題材 c2・c3・c4（正解は W20 のまま）。
- 設定: `baseline-both`（Sonnet）。依頼文は道具なし + W29 の要件を照らす指示 + W28 の本番で起動して確かめる指示（応答の状態コードとエラーの表示を確かめる、を足した）。比べる相手は W27〜W29 の Sonnet。
- 本数: 3 題材 × 2 回 = 6 本。手順・許可リストは W28 と同じ。判定は W20 と同じ基準・同じ判定役。
