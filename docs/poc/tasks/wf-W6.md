ログイン中のユーザーが、自分が担当するタスクを確認・追加・更新できる「マイタスク」画面（/my-tasks）を追加し、ブラウザで確認してから PR を作成するところまで進めてください。スマートフォンでも使える画面にします。仕様は次のとおりです。

## 画面の内容

- ページの見出し（`h1`）は「マイタスク」。ヘッダー（ログイン中に表示される部分）に、この画面への「マイタスク」というリンクを追加する。
- 未ログインで開いたときは、ログイン画面（/login）に移動する。
- ログイン中のユーザーが担当者になっているタスクだけを、期限の近い順（同じ期限なら ID の小さい順）に並べる。ほかの人が担当のタスクは表示しない。
- 各タスクは `data-testid="my-task"` の要素とし、タイトル（タスク詳細画面 /tasks/:id へのリンク）・ステータス・期限（例: `2026-11-14`）を表示する。
- 担当しているタスクが 1 件も無いときは、一覧の代わりに「担当しているタスクはありません。」と表示する。下の追加フォームは表示したままにする。

## タスクの追加

- `<form aria-label="タスクの追加">` の中に、ラベル付きの入力欄「タイトル」（`name="title"`）と「期限」（`name="dueDate"`、`type="date"`）、「追加する」ボタンを置く。担当者はログイン中のユーザー、ステータスは「未着手」で登録する。
- 追加に成功したら、ページを再読み込みしなくても（再読み込みしてもよい）一覧に表示され、入力欄は空に戻る。
- 送信中は「追加する」ボタンを押せないようにし、二重に登録されないようにする。
- 入力に誤りがあるとき（タイトルが空白だけ、など）は、フォームの近くに `role="alert"` でエラーの理由（例: 「タイトルは 1〜200 文字で入力してください」）を表示する。入力した内容は消さない。直して追加し直せたら、エラーの表示は消す。
- 通信に失敗したとき・サーバーがエラー（500 など）を返したときは、フォームの近くに `role="alert"` で「追加できませんでした。時間をおいてもう一度お試しください。」と表示する。入力した内容は消さない。

## ステータスの変更

- 各タスクのステータスは、ラベル付きの選択欄（`<select>`。選択肢は 未着手・進行中・完了。ラベルには「ステータス」を含める）で表示し、選んだらすぐに保存する。
- 保存に失敗したときは、そのタスクの近くに `role="alert"` で「ステータスを変更できませんでした。」と表示し、選択欄を元の値に戻す。

## スマートフォン対応

- 幅 375px の画面でも横にスクロールせずに使えること。ページ全体（ヘッダーを含む）が画面の幅に収まり、各タスクのタイトル・ステータス・期限と、追加フォームの入力欄・ボタンが画面の幅の中に表示される。
- 幅 1280px の画面でも崩れないこと。

## 確認と PR

- 実装したら、実際のブラウザで画面を操作して確認してください（スマートフォンの幅を含む）。確認に使ったスクリーンショットなどの証跡はリポジトリ内に保存してコミットし、PR の本文から参照してください。
- この環境にはリモートリポジトリが無いため、push と PR の作成（GitHub への送信）はできません。PR を作成する工程では、作成するはずだった PR のタイトルと本文を、リポジトリ直下の `PR.md` に書いてコミットしてください。
