# W27 の設計: 実際の試行の不具合でも「動かして確かめる」は効くか

- 作成: 2026-11-11（試行の前に固定）
- 依頼: ユーザー「結果から学習して新しい PoC をやっておいて」。W24〜W26 の結果から、コーディネーターが代理人の原則（`docs/poc/proxy/principles.md`）で設計した。判断の記録は `docs/poc/results/workflow/W27/decisions.md`。

## 1. 何を確かめるか

- W24〜W26 の題材は、どれも担当が作った作り物だった。W27 は、**これまでの PoC の試行で実際に起きた不具合**（W20 の評価セット）で、「動かして確かめる」指示が見落としを減らすかを確かめる。
- 特に、W20 の 35 本のレビューのどれも見つけなかった「本番で詳細の画面が 500」（W20 c2 の B1）を、動かして確かめれば見つけられるかを見る。

## 2. 評価セット・設定・本数

- 題材: W20 の実際の 3 題材（`docs/poc/answer-key/W20/cases/` の c2・c3・c4。正解は W20 のまま）。
  - c2: W19 superpowers 1（B1 本番で詳細の画面が 500・G1・G2 要件の抜け）
  - c3: W14 superpowers 2（B1〜B4）
  - c4: W15 gstack 2（B1・B2）
- 設定: Sonnet の `baseline`（道具なし）と `baseline-run`（W24 と同じ「動かして確かめる」指示を依頼文に足す）。
- 本数: 3 題材 × 2 設定 × 2 回 = 12 本。手順は W20 と同じ（各題材の初期状態と汎用の開発標準を当てる）。許可リストは W21 以降と同じ（`node`・`npm test`・`npm run build`・`npx next` を許可）。
- 判定: W20 と同じ判定役の指示文・基準。比べる相手として、W20 の各道具の結果（`/code-review`・`/review-pr`・Superpowers）も並べる。
