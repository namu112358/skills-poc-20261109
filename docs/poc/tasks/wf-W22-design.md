# W22 の設計: レビューの道具が効く条件を探す（弱いモデル・手順を最後まで）

- 作成: 2026-11-11（試行の前に固定）
- 依頼: ユーザー「今の PoC が終わったら、その結果から学習して新しいのをやっておいて」。W21 の結果から、コーディネーターが代理人の原則（`docs/poc/proxy/principles.md`）で設計した。判断の記録は `docs/poc/results/workflow/W22/decisions.md`。

## 1. W21 から分かったことと、次に確かめること

- W21（Sonnet・道具の既定の動き）では、見つけた数がどの設定もほぼ満点で、差は雑音と費用だけだった。
- 道具が効くとすれば、次の 2 つの条件が考えられる。W22 はこの 2 つを、W21 と同じ題材・同じ正解で確かめる（W21 と直接比べられる）。
  1. **弱いモデル（Haiku）**: モデルの力が足りないとき、道具の手順（観点の一覧・専門のエージェント・検証）が見落としを補うか。補うなら、安いモデルと道具の組み合わせが、Sonnet の道具なしに近づくか。
  2. **道具の手順を最後まで踏ませる（Sonnet）**: W21 では `/review-pr` が 14 本中 13 本で専門エージェントを起動せず、`ce-code-review` は軽い型（lite）を選んだ。手順を最後まで踏ませたとき、見つける数・雑音・費用がどう変わるか。

## 2. 評価セット

W21 と同じ（`docs/poc/answer-key/W21/cases/` の c1〜c7 と正解）。題材・正解・判定の基準は変えない。

## 3. 比べる設定

| 設定 | モデル | レビューの段で送るもの | 比べる相手（W21） |
|---|---|---|---|
| `hk-baseline` | Haiku（`claude-haiku-5-5`） | 道具の指定なし | `baseline` |
| `hk-cr-high` | Haiku | `/code-review high` | `cr-high` |
| `hk-review-pr` | Haiku | `/pr-review-toolkit:review-pr all` | `review-pr` |
| `hk-principles` | Haiku | `/design-principles-review` | `principles` |
| `hk-ce-review` | Haiku | `/ce-code-review base:HEAD` | `ce-review` |
| `review-pr-full` | Sonnet | `/review-pr all` に「手順どおり専門のレビューエージェントを Task で並列に起動して、結果をまとめる。自分だけで済ませない」を足す | `review-pr` |
| `ce-full` | Sonnet | `/ce-code-review base:HEAD depth:full`（深さの判定を飛ばして全員を起動） | `ce-review` |

- 手順（依頼 → レビュー → 書き写し）・許可リスト（`node` の実行を含む）・介入（最大 1 回）は W21 と同じ。
- 試行 ID: `W22-<設定>-<題材>-<回>`。回 0 は動作確認で集計に入れない。

## 4. 本数

- Haiku の 5 設定: 7 題材 × 1 回 = 35 本（W21 で、見つけた数は回による揺れがほぼ無かったため 1 回。差が出た組だけ 2 回目を足す）。
- 手順を最後まで踏ませる 2 設定: 7 題材 × 2 回 = 28 本（W21 の同じ設定と 2 回どうしで比べる）。
- 計 63 本。並列 2 本。

## 5. 測るもの・判定

- W21 と同じ（見つけた数〔B・P・I1〕・誤った指摘・雑音・費用・時間）。加えて、サブエージェントの数（手順を踏んだか）。
- 判定は W21 と同じ判定役（Opus）・同じ指示文・設定を伏せた資料。約 25% を 2 回判定する。W21 の判定は使い回し、W21 と W22 を並べて読む。
