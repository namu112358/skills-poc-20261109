# W22 の設計: デザインの Skill を確実に使わせる指示の効果

- 作成: 2026-11-11（W21 の試行中。試行の前に固定）
- 依頼者の指示（不在の間、検証結果から新たな PoC を検討して進める）を受けて、コーディネーターが W21 の途中の結果から立てた。
- 題材・採点・人の評価は W21 と同じ（[wf-W21-design.md](wf-W21-design.md)）。W21 の結果と同じ場で比べられるよう、試行 ID は `W21<課題>-<構成>-<回>` の形にし、順位付けのページにも名前を伏せて混ぜる。

## 1. きっかけ（W21 の途中の結果）

依頼文を渡すだけ（Skill の自動発火）だと、デザインの Skill が呼ばれないことが多い。2026-11-11 時点の作る課題（W21a・W21b）では次のとおり。

| 構成 | Skill が呼ばれた試行 |
|---|---|
| 4 つすべて（`ui-all`） | 0 / 3 |
| UI/UX Pro Max（`ui-pm`） | 1 / 4 |
| Impeccable（`ui-a`） | 2 / 3 |
| Frontend Design（`ui-fd`） | 3 / 3 |

ツールを入れても使われなければ、入れていないのと同じになる。標準の構成を決めるには、「どのツールを入れるか」に加えて「どう使わせるか」も決める必要がある。

## 2. 問い

1. 各プロジェクトの `CLAUDE.md` に「画面を作るときはこの Skill を使う」と書けば、Skill が確実に呼ばれるか。
2. 呼ばれるようになると、画面の出来（人の評価）と費用はどう変わるか。
3. 4 つすべてを入れたままでも、`CLAUDE.md` で役割を割り振れば（作る = Impeccable、レビュー = Web Design Guidelines、UI/UX Pro Max は使わない）、今の標準のまま使えるか。

## 3. 比べる構成

ツールの出し入れは W21 の同じ名前の構成と同じ。違いは、作業用コピーのアプリの `CLAUDE.md` の末尾に足す指示だけ（初期状態の一部なので、候補からは差分に見えない）。

| 構成 | ツール | `CLAUDE.md` に足す指示 | 比べる相手（W21） |
|---|---|---|---|
| `ui-fd-md` | Frontend Design + Web Design Guidelines | 画面を作る・変えるときは、最初に `frontend-design` Skill を使う | `ui-fd` |
| `ui-a-md` | Impeccable + Web Design Guidelines | 画面を作る・変えるときは、最初に `impeccable` Skill を使う | `ui-a` |
| `ui-all-md` | 4 つすべて | 画面を作る・変えるときは `impeccable` Skill を使う。画面の変更をレビューするときは `web-design-guidelines` Skill を使う。`frontend-design` と `ui-ux-pro-max` の Skill は使わない | `ui-all` |

指示の文面は `docs/poc/tasks/wf-W22-<構成>.md`（固定）。

## 4. 課題と試行

- 課題: W21d（SaaS の LP）・W21e（ダッシュボード）・W21f（登録フォーム）。W21 の題材を広げた 3 つで、W21 の比べる相手も各 4 回ある。
- 3 構成 × 3 課題 × 3 回 = 27 本。W21 の試行がすべて終わってから流す（並列は 3 本まで）。
- 手順・許可リスト・介入・モデルは W21 と同じ。

## 5. 測るもの

| 指標 | 測り方 |
|---|---|
| Skill が呼ばれた割合 | 実行記録の `Skill` の呼び出し（指定した Skill が呼ばれたか） |
| 画面の出来 | W21 と同じ: 人の順位付け（主）、機械の検査（足切り）、AI の判定（補助） |
| 費用・時間 | W21 と同じ |

判定: 指定した Skill が呼ばれた割合が、比べる相手より明らかに上がり（9 回中 8 回以上）、人の評価が下がらず、費用の増え方が 2 倍以内なら、「`CLAUDE.md` で使う Skill を指定する」を標準の配り方に入れる。

## 6. 限界

- 指示は 1 つの書き方だけを試す。言い回しで結果が変わる可能性がある。
- 人の評価者は依頼者 1 名。
