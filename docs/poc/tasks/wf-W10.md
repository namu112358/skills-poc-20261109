タスクの期限を延長する「延長申請」の仕組みを追加してください。タスクの担当者が期限に間に合わないとき、新しい期限と理由を添えて延長を申請し、ほかのメンバーが申請を確認して承認または却下します。承認されると、タスクの期限が新しい期限に変わります。利用者は全員日本国内にいます。今回は API だけを作り、画面は別の作業で作ります。仕様は次のとおりです。

## データ

- 延長申請は次の項目を持つ: ID（整数）、対象のタスク、申請者（ユーザー）、新しい期限、理由、状態、申請日時、判断した人、判断日時。
- 状態は「保留中（`pending`）」「承認（`approved`）」「却下（`rejected`）」のいずれか。申請した時点では保留中。
- 新しい期限は、タスクの期限（`dueDate`）と同じ `YYYY-MM-DD` 形式の日付。
- 申請日時・判断日時は ISO 8601 形式の UTC（例: `2026-11-09T03:04:05.000Z`）で保存する。判断されるまでは、判断した人・判断日時は `null`。
- 1 つのタスクにつき、保留中の申請は同時に 1 件まで。

## API

すべてログインが必要。未ログインなら 401 を返す。エラーは既存の API と同じ `{ error, details? }` の JSON で返す。
延長申請は次の JSON で表す。

```json
{
  "id": 1, "taskId": 3, "requester": "sato", "newDueDate": "2026-11-20", "reason": "レビュー待ちのため",
  "status": "pending", "createdAt": "2026-11-09T03:04:05.000Z", "decidedBy": null, "decidedAt": null
}
```

| メソッドとパス | 動作 | 成功時 |
|---|---|---|
| `GET /api/tasks/:id/extensions` | そのタスクの延長申請を、申請の古い順に返す | 200 `{ "extensions": [ ... ] }`（無ければ空配列） |
| `POST /api/tasks/:id/extensions` | 本文 `{ "newDueDate": "2026-11-20", "reason": "..." }` で延長を申請する | 201 `{ "extension": { ... } }` |
| `POST /api/tasks/:id/extensions/:extensionId/approve` | 申請を承認し、タスクの期限を新しい期限に変える | 200 `{ "extension": { ... }, "task": { ... } }`（`task` は既存の API と同じ形の、変更後のタスク） |
| `POST /api/tasks/:id/extensions/:extensionId/reject` | 申請を却下する（タスクの期限は変わらない） | 200 `{ "extension": { ... } }` |

- タスクが存在しない（ID が正の整数でない場合も含む）ときは 404。延長申請が見つからないときも 404。
- 申請者は、ログイン中のユーザーにする。
- 新しい期限が `YYYY-MM-DD` 形式でない、または理由が 1〜500 文字でないときは 400（`details` に理由）。
- 保留中の申請があるタスクに、さらに申請したら 409。
- 承認・却下すると、状態を変え、判断した人（ログイン中のユーザー）と判断日時を記録する。
- 承認すると、そのタスクの期限（`GET /api/tasks/:id` などで返す `dueDate`）が新しい期限になる。
