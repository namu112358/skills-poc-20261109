# W21c の正解（UI レビュー。review.patch に仕込んだ問題）

review.patch は W6 の参照実装（`docs/poc/answer-key/W6/reference.patch`）の「マイタスク」画面に、画面の見た目・使い勝手・アクセシビリティの問題を仕込んだもの。場所はすべて `src/app/my-tasks/MyTasks.tsx`。

### 仕込んだ問題（9 件）

| 番号 | 種類 | 場所 | 問題（誰が・どういう状況で困るか） | 正しい直し方 |
|---|---|---|---|---|
| B1 | ラベルの欠落 | 追加フォームのタイトル欄（`<input name="title" placeholder="タイトル">`） | 見えるラベルが無く、プレースホルダだけ。入力を始めると何の欄か分からなくなり、スクリーンリーダーでは欄の名前が読まれない（プレースホルダは名前の代わりにならない） | `<label>タイトル <input …/></label>`（または `aria-labelledby`）で見えるラベルを付ける |
| B2 | エラーが伝わらない | 追加フォームのエラー表示（`addErrors` の `<div style={{ color: … }}>`） | `role="alert"`（または `aria-live`）が無く、入力誤り・通信失敗のエラーがスクリーンリーダーで読まれない。PR の説明の「フォームの近くにエラーを表示」は、目の見えない利用者には伝わらない | エラーの入れ物に `role="alert"` を付ける（必要なら入力欄に `aria-invalid`・`aria-describedby`） |
| B3 | 文字のコントラスト不足 | 期限の表示（`color: "#b0b0b0"`、13px） | 白地に #b0b0b0 はコントラスト比が約 2.1:1 で、WCAG の 4.5:1 に届かない。弱視の人や屋外のスマートフォンで期限が読めない | 4.5:1 以上の色（例: #595959 より濃い色）にする |
| B4 | 狭い画面での横スクロール | 一覧の各行（`gridTemplateColumns: "320px 200px 120px"`、`minWidth: 640`） | 幅 375px のスマートフォンでは一覧がはみ出し、画面全体が横にスクロールする。期限やステータスが画面外に出る。PR の説明の「スマートフォンでも使える」に反する | 固定幅・`minWidth` をやめ、狭い幅では縦に並べる（`flex-wrap`・`minmax`・メディアクエリなど） |
| B5 | フォーカスの見た目を消している | `fieldStyle` の `outline: "none"`（ステータスの選択欄・タイトル欄・期限の欄） | キーボードで操作する人が、どの欄にフォーカスがあるか分からない。代わりのフォーカス表示も無い | `outline: none` を外す。消すなら `:focus-visible` で代わりの見た目を付ける |
| B6 | 名前の無いボタン | タイトル欄の横の「×」ボタン | アイコン（記号）だけで名前が無く、スクリーンリーダーでは「かける」などと読まれ、何のボタンか分からない。見た目でも「削除」か「クリア」か分かりにくい | `aria-label="タイトルを消す"` を付ける（見える文言にしてもよい） |
| B7 | 色だけで情報を伝えている | 期限の表示（期限切れのときだけ文字を赤 `#d32f2f`） | 期限切れかどうかを文字色だけで示している。色の見分けがつきにくい人には区別できない | 「期限切れ」の文字やアイコンなど、色以外の手がかりを足す |
| B8 | 二重送信 | 追加フォームの送信（`add`）と「追加する」ボタン | 送信中にボタンを押せないようにしていない（送信中の状態も無い）。通信が遅いときに連打すると同じタスクが 2 件以上登録される。送信中であることも利用者に見えない | 送信中の状態を持ち、送信中はボタンを `disabled` にする（「追加中…」などを表示） |
| B9 | 操作の的が小さい | ステータスの選択欄（`fontSize: 11, height: 20, padding: 0`） | 高さ 20px・文字 11px で、スマートフォンの指では押しにくく、文字も読みにくい（iOS では 16px 未満の入力欄でフォーカス時に拡大される） | 高さ 44px 前後（少なくとも 24px 以上）、文字は 16px 程度にする |

### おとり（問題ではない点。問題だと指摘したら誤った指摘）

| 番号 | 場所 | 見た目 | 正しい理由 |
|---|---|---|---|
| D1 | 全体の書体（`system-ui`） | 書体を指定していない・ありふれている | アプリ全体の既定（`layout.tsx`）と同じ。この PR の範囲で変えるものではない |
| D2 | 期限の表示形式 `2026-11-14` | 日本語の日付（11月14日）でない | 既存のタスク一覧画面と同じ形式。仕様どおり |
| D3 | インラインの `style` | CSS ファイル・クラスを使っていない | 既存の画面（`layout.tsx`・W6 までの画面）と同じ書き方。新しいライブラリを足さない規約もある |
| D4 | ステータスの変更を先に画面に反映し、失敗したら戻す | 保存前に表示が変わる | 意図した楽観的更新。失敗時は `role="alert"` で知らせて元に戻している |
| D5 | `<form aria-label="タスクの追加">` と見出し「タスクを追加」 | 名前が重複している | フォームの名前（ランドマーク）と見出しは役割が違う。問題ではない |

`D1`〜`D5` を「問題がある」と指摘した場合は誤った指摘に数える（「問題ない」と書いただけなら数えない）。ステータス変更のエラー（`<p role="alert">`）は正しく、指摘の対象ではない。
