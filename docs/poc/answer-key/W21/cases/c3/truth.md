# C3 の正解（CSV の出力）

| ID | 種類 | 場所 | 仕組み（核心） | 正しい直し方 |
|---|---|---|---|---|
| B1 | エスケープ漏れ | `src/lib/export.ts` の `field` | 値をダブルクォートで囲むだけで、値の中の `"` を `""` に重ねていない。タイトルに `"` があると項目が途中で閉じ、列がずれる・行が壊れる（PR の説明「引用符が含まれていても列がずれない」に反する） | `"${String(value).replaceAll('"', '""')}"` にする |
| B2 | 規約違反（クエリの検証） | `src/app/api/tasks/export/route.ts` の `status`（`as TaskStatus \| null`） | `status` を型ガードで検証せず、型の断定だけで `listTasks` に渡している（規約 2 違反）。`?status=foo` のような不正な値で、「指定なし」（全件）ではなく見出しだけの空の CSV になる。PR の説明「不正な値は一覧と同じく指定なし」にも反する | `isTaskStatus(status) ? status : undefined` で検証してから渡す |
| B3 | テストが確かめていない | `tests/export.test.ts` の "escapes quotes and commas in titles" | テストの名前はカンマ・引用符のエスケープを確かめるとしているが、入力のタイトル（`週次 定例の準備`）にカンマも引用符も無いため、何も確かめていない。B1 を見逃している | 引用符・カンマ・改行を含むタイトルで、`""` への置き換えと列の数を確かめる |

### おとり（不具合ではない変更。指摘したら誤った指摘）

| ID | 場所 | 見た目 | 正しい理由 |
|---|---|---|---|
| D1 | `CSV_BOM`（`"﻿"` を先頭に付ける） | 見えない文字を先頭に付けている／データが汚れる | PR の説明のとおり、Excel で UTF-8 の CSV を文字化けさせないための BOM。意図どおり |
| D2 | 行の区切りが `\r\n` | 改行コードが LF でない | CSV の仕様（RFC 4180）と Excel の既定どおり |
| D3 | 全項目をダブルクォートで囲む | 数値まで囲んでいる | 囲むこと自体は CSV として正しい（問題は B1 の中の `"` の扱い） |

- 一致の基準: 場所（ファイルと関数）と仕組みの核心の両方を述べていれば一致。
- 数式の埋め込み（`=` で始まるタイトルが Excel で数式になる）の指摘は、正解外の妥当な指摘として扱う。
