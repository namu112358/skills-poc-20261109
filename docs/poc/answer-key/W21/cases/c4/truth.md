# C4 の正解（期限が近いタスクの判定）

| ID | 種類 | 場所 | 仕組み（核心） | 正しい直し方 |
|---|---|---|---|---|
| B1 | 日付の計算（時刻と時差） | `src/lib/due.ts` の `daysUntilDue` | 日付ではなく時刻の差で数えている。`Date.parse("YYYY-MM-DD")` は UTC の 0 時（日本時間の 9 時）なので、日本時間の 9 時を過ぎると、今日が期限のタスクが `-1`（期限切れ）になり「期限間近」が付かない。日中のほとんどの時間で、今日が期限のタスクが目立たなくなる。テストは日本時間 0 時の固定の時刻だけで確かめているので気づかない | `now` を日本時間の日付（`Intl.DateTimeFormat("sv-SE", { timeZone: "Asia/Tokyo" })` など）に直し、日付どうしの差（日数）で数える |
| B2 | 境界値 | `src/lib/due.ts` の `isDueSoon`（`days < DUE_SOON_DAYS`） | PR の説明は「今日から 3 日以内（3 日後を含む）」だが、`< 3` なので 3 日後が含まれない（B1 を直すと常に、直さなくても日本時間 0〜9 時は 3 日後に付かない） | `days <= DUE_SOON_DAYS` にし、3 日後・4 日後の境界のテストを足す |

### おとり（不具合ではない変更。指摘したら誤った指摘）

| ID | 場所 | 見た目 | 正しい理由 |
|---|---|---|---|
| D1 | 完了したタスクを除く（`task.status === "done"` なら false） | 条件の抜け | PR の説明どおり、完了したタスクには付けない |
| D2 | `now: Date = new Date()` の既定の引数 | テストしにくい・時刻に依存 | テストでは `now` を渡しており、既定値は画面用。依存を引数で差し替えられる形になっている |

- 一致の基準: 場所（ファイルと関数）と仕組みの核心の両方を述べていれば一致。B1 は「UTC と日本時間のずれ」「時刻の差で数えている／9 時以降に今日が期限切れ扱いになる」のどれかを述べていれば一致。サーバーのタイムゾーンの一般論（「タイムゾーンに注意」だけ）は一致にしない。
