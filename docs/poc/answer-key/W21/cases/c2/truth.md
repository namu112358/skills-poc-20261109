# C2 の正解（不具合の無い差分。怪しく見えるが正しい箇所がある）

仕込んだ不具合は無い。指摘はすべて、正解外の妥当な指摘・細かい点・誤った指摘のどれかになる。

### おとり（不具合ではない変更。指摘したら誤った指摘）

| ID | 場所 | 見た目 | 正しい理由 |
|---|---|---|---|
| D1 | `listTasks` の `ORDER BY ${SORT_COLUMNS[filter.sort ?? "id"]}, id`（`src/lib/tasks.ts`） | テンプレート文字列で SQL を組み立てている（SQL インジェクション・規約 8 違反に見える） | SQL に入るのはコード内の表 `SORT_COLUMNS` の値（`id`・`due_date`）だけ。利用者の値は `isTaskSort` で検証され、表を引くキーにしか使われない。規約 8 は「値」の埋め込みの決まりで、列名はプレースホルダにできない |
| D2 | `GET /api/tasks`・一覧の画面の、不正な `sort` を登録順として扱う処理 | 入力の誤りを 400 にせず黙って無視している | コーディング規約 2「URL のクエリパラメータは型ガードで検証し、不正な値は『指定なし』として扱う」のとおり。既存の `status` と同じ扱い |
| D3 | `isTaskSort` の `includes` による判定 | `__proto__` などで表の外の値を引ける／プロトタイプ汚染に見える | `TASK_SORTS` の配列に含まれる値だけを通す（テストでも `__proto__` を拒むことを確かめている） |
| D4 | `ORDER BY due_date` | 日付を文字列で並べている | 期限は `YYYY-MM-DD` 形式で検証して保存しているので、文字列の順と日付の順が一致する |

- D1〜D4 に対して「問題がある」と指摘した場合は誤った指摘に数える（「問題ない」と書いただけなら数えない）。
