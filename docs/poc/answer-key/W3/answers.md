# W3 定型回答シート（依頼者役が使う）

試行を始める前（2026-11-09）に固定した。試行中・採点中は変えない。
このシートは試行の作業用コピー（`.poc-work/`）には入れず、`scripts/poc/answer_w3.py` の回答役だけが読む。

依頼者: 開発チームのリーダー、佐藤。依頼文は「チームの進捗が見えにくいので、何とかしたいです。」だけ。

## 回答のルール

1. 聞かれたこと（または提案の中で触れられたこと）にだけ答える。聞かれていない項目は、関係が深そうでも自分から言わない。
2. 答えるときは、下の該当項目の内容をそのまま、または短く言い換えて伝える。シートに無い内容を付け足さない。
3. シートに無いことを聞かれたら「お任せします」と答える。
4. 案の選択・進め方・「この理解でよいか」の確認を求められたら、シートと矛盾しなければ「はい、それで進めてください」（複数案なら「推奨の案で進めてください」）。シートと矛盾する点があれば、その点だけを該当項目に沿って訂正する。
5. 1 つのメッセージに複数の質問があれば、すべてに番号を付けて答える。

## 背景（聞かれたら答えてよい）

- **B1 依頼者とチーム**: 依頼者は開発チームのリーダーの佐藤。チームは 3 人（佐藤・鈴木・田中）で、このタスク管理アプリを社内で使っている。
- **B2 いまの困りごと**: 毎週の定例で、各自に口頭で状況を聞いて回っている。タスク一覧は全件が並ぶだけで、誰がどれくらい抱えていて、どれが遅れているかがひと目で分からない。
- **B3 使う場面**: 毎週月曜の朝の定例（15 分）で、画面を共有して全員で見る。
- **B4 目的の種類**: 社内向けの業務改善。売り物ではない。

## 隠れ要件（採点の対象。聞かれたら答える）

- **H1 主な利用者と目的**: 主に見るのはリーダーの私。定例で、遅れているタスクを早く見つけて手を打ちたい。メンバーも見てよい。
- **H2 担当者ごとの状態別の件数**: 担当者ごとに、未着手・進行中・完了の件数を表で見たい。担当者は名前（佐藤など）で表示してほしい（いまの一覧は ID が出ている）。
- **H3 期限切れ**: 期限を過ぎていて完了していないタスクを、いちばん目立つように出したい。件数と、タスクの一覧（担当者・期限・何日過ぎたか）。
- **H4 期限が近いもの**: 今日を含めて 7 日以内に期限が来る未完了のタスクも、期限切れとは別に分かるようにしたい。
- **H5 今週の完了数**: 今週（月曜〜日曜）完了したタスクの数を、担当者ごとに見たい。いまは完了した日が残っていないので、ステータスを完了にした日時を記録してほしい。完了から別のステータスに戻したら、その記録は消してよい。過去の分を埋める必要はない（記録を始めてからでよい）。
- **H6 日付の基準**: 期限切れ・7 日以内・今週の判定は、日本時間（JST）の日付で行う。
- **H7 見られる人**: ログインしている人なら誰でも、全員分を見られてよい（チーム内で隠すものはない）。ログインしていない人には見せない。
- **H8 画面の置き場所**: 新しく「進捗」の画面を作り、ヘッダーから行けるようにしてほしい。いまのタスク一覧の表示や絞り込みは変えないでほしい。
- **H9 件数から一覧へ**: 担当者ごとの件数をクリックしたら、その担当者・そのステータスで絞り込んだタスク一覧に移れるとよい。いまの一覧は担当者で絞り込めないので、担当者の絞り込みを足すのはかまわない（いまの表示とステータスの絞り込みはそのまま）。
- **H10 スマホ**: 定例にスマホで参加する人がいるので、スマホの幅でも横にスクロールせずに読めるようにしたい。

## スコープ（聞かれたら・提案されたら答える）

- **S1 通知**: メールや Slack などの通知は、今回は要らない。
- **S2 入力の追加**: 進捗率（%）や工数の入力は要らない。メンバーの入力の手間を増やしたくない。いまあるステータスと期限だけで分かるようにしたい。
- **S3 グラフ**: グラフ・ガントチャート・バーンダウンチャートは要らない。数字と表で十分（新しいライブラリも入れない方針）。
- **S4 時期**: 2 週間以内に最初の版を使い始めたい。まずは最低限で、足りなければ後で足す。
- **S5 推移**: 過去からの推移（先週との比較など）は、今回は要らない。
