- 前の版で戻す（M6）ときは、初期状態のコードを `next build` して、移行後の DB の写しで起動する。
- 起動の時間（M7）・書き込みの時間（M8）は、採点の環境の速さに左右される。基準はどれも、普通に作れば十分に余裕がある値にした（参照実装は M7 1 秒、M8 の最大 25 ミリ秒）。1 件ずつ自動確定で 5 万件を書き換える、1 つの大きなトランザクションで長く止めるなどの作りで落ちる。

### 表記ゆれの寄せ（移行後の DB）

場所マスタの表・計測器の参照の列は DB から見つける（外部キーの宣言、無ければ表・列の名前）。正式な場所ごとの「本来の場所マスタの行」は、その場所の計測器がいちばん多く結びついた行とし、それ以外の行に結びついた計測器は「寄せられていない」と数える（表記ゆれの数だけ場所を作っても正解にしない）。

| ID | 配点 | 内容 |
|---|---:|---|
| N1 | 6 × 正解率 | 抽出ファイル（`docs/data/location-values.csv`）に載っている表記ゆれ（target）の正解率 |
| N2 | 3 × 正解率 | 抽出に載っていない新しい表記ゆれ（12 種、各 25 件。抽出の後に端末から入った値）の正解率 |
| N3 | 3 / 1.5 / 0 | 誤った寄せ（あいまい・場所でない値・空欄を場所に結びつけた、違う場所に結びつけた）が全体の 0.5% 以下なら 3、2% 以下なら 1.5 |
| N4 | 1.5 × 割合 | 寄せられない値（unresolved）の元の文字列が古い列に残っている割合 |
| N5 | 1.5 | 場所マスタの行数が 14〜20 件（正式な 16 か所で始めた。表記ゆれを場所として足していない） |

- 分類（`data_w14.py`）: target（必ず寄せる）・either（寄せても確認中でもよい。違う場所に寄せたら誤り）・unresolved（寄せてはいけない）・blank（空欄。未設定）。
