# W18 第 6 回「部署ごとの権限」の回答シート

依頼文（`docs/poc/tasks/wf-W18r6.md`）:

> ほかの部署の計測器を、関係ない人が台帳で書き換えられてしまう。部署ごとに、できることを分けてほしい。

隠しテストは `f6.cjs`（G01〜G08）。

## 業務の決まり（Q。隠れ要件）

| ID | 内容 | 隠しテスト |
|---|---|---|
| Q1 | 計測器の「管理部署」は、その計測器の管理者が所属する部署。管理者が退職・休職で無効になっていても、その人の部署が管理部署。管理者を別の部署の人に変えたら、管理部署も変わる。 | G07 |
| Q2 | 台帳の編集（重要度・設置場所・状態を含む）、校正記録の登録、校正の発注、貸出・返却は、その計測器の管理部署の人と、品質保証部の人だけができる。 | G01・G03・G04 |
| Q3 | 計測器の新しい登録は、品質保証部だけができる（台帳の取りまとめのため）。 | G02 |
| Q4 | 場所の一覧の追加・名前の変更・削除は、品質保証部だけができる。 | G06 |
| Q5 | 一覧・詳細・履歴を見ることと、予約（自分の予約を作る・取り消す）は、全員ができる。予約を取り消せる人は今までどおり（本人と管理者）。 | G05 |
| Q6 | 権限が無い操作をしたら、「権限がありません」と分かるようにしてほしい（API では 403）。画面では、できない操作のボタンは出さなくてよい。 | G08 |
| Q7 | 定期実行のジョブ（運用の cron）は今までどおり動くようにしてほしい。 | G08 |
| Q8 | 品質保証部は、部署の一覧の「品質保証部」（今の部署の ID は `qa`）。 | （テストなし） |

## 文書・既存の仕組みに既に書いてあること（D）

| ID | 内容 | 場所 |
|---|---|---|
| D1 | 利用者は部署に所属する。無効な利用者はログインできない。部署には代表者がいる | `CLAUDE.md`・既存のコード |
| D2 | 定期実行のジョブは利用者ではなく `JOBS_TOKEN` で認証する | `docs/operations.md` |

## 範囲の外・決めていないこと（「お任せします」）

- 権限の設定画面（部署ごとの権限を画面で変える仕組み）。今回は決まった分け方でよい。
- 代表者に特別な権限を与えるか（今は与えない。聞かれたら「要らない」）。
- 部署をまたぐ貸出（他部署の人に貸すこと）は今までどおりできる（貸す操作をするのは管理部署か品質保証部の人）。
