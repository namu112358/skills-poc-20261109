## アダプター

API の名前・値（重要度の項目と値、予約・場所・発注・履歴・副管理者の API、状態の値）は候補が決めるため、テストはアダプター（JSON）を通して操作する。形は `adapters/reference.json`。

1. 各回の採点の前に、`adapt_w18.py` が別の `claude -p`（ツールなし）に、候補のコード（初期状態から足された・変わったファイル）と前の回で確定したアダプターを渡して下書きを作る（`results/workflow/W18/adapters/<系列ID>-r<回>.draft.json`）。
2. 採点者はコードと見比べて確かめ、`<系列ID>-r<回>.json`（引き継ぎは `-h1`・`-h2`）として確定する。前の回のセクションは、API が変わっていなければそのまま写す。
3. 採点者が補正してよいのは「候補の実装が実際に持っている名前・値・API を指す」ことだけ。候補に無い機能を足す補正はしない。API の名前が回の途中で変わった（古い API を消して新しい API にした）ときは、新しい API を指し、そのことを report の判断の記録に書く（後退には数えない。振る舞いが変わったら後退）。
4. 候補が文書と違う名前の環境変数で通知サービス・受付システムを読む場合は、アダプターの `env` で同じ値を渡して動かし、report に書く。
