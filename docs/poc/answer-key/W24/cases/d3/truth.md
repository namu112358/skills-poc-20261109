# D3 の正解（ダッシュボードとコメントを 1 つの PR にまとめたもの。d1 と d2 の和）

| ID | 種類 | 場所 | 仕組み（核心） | 正しい直し方 |
|---|---|---|---|---|
| B1 | 利用者をまたぐキャッシュ | `src/lib/dashboard.ts` の `buildDashboard`（`cached("dashboard", …)`） | キャッシュのキーが固定の `"dashboard"` で利用者を含まないため、30 秒以内にほかの人が開くと、最初に開いた人のダッシュボード（担当タスク・件数）がそのまま返る。他人の情報が見える | キーに利用者の ID を含める。または利用者ごとにキャッシュしない |
| B2 | 週の境界（日曜） | `src/lib/week.ts` の `weekRange` | `getUTCDay()` は日曜が 0 なので、`1 - dow` が +1 になり、日曜には翌週の月〜日を返す。日曜には「今週が期限」に今週のタスクが出ず、翌週のタスクが出る。テストは水曜だけで確かめている | 月曜からの日数を `(getUTCDay() + 6) % 7` で求める。日曜・月曜のテストを足す |
| B3 | 0 での割り算 | `src/lib/dashboard.ts` の `completionRate` | 担当タスクが 0 件の人では `0 / 0` で `NaN` になり、画面に「完了率 NaN%」と出る（API では `null` になる） | 0 件のときは 0（または「—」）を返す |
| B4 | 共有の定数の書き換え | `src/lib/dashboard.ts` の `countByStatus`（`(TASK_STATUSES as TaskStatus[]).reverse()`） | `reverse()` は配列をその場で並べ替えるので、アプリ全体で共有する `TASK_STATUSES` が呼ぶたびに逆になる。ダッシュボードの並びが表示のたびに入れ替わり、一覧の絞り込みの選択肢の並びも変わる。`readonly` を型の断定で外している | 写してから並べ替える（`[...TASK_STATUSES].reverse()`） |
| B5 | 規約違反（SQL の組み立て） | `src/lib/dashboard.ts` の `listAssignedTasks` | 利用者の ID をテンプレート文字列で SQL に埋め込んでいる（規約 8 違反）。ID に引用符を含むと SQL が壊れる | プレースホルダ（`WHERE assignee = ?`）にする |
| B6 | XSS（リンクの URL） | `src/lib/comments.ts` の `renderBody` と、詳細画面の `dangerouslySetInnerHTML` | 本文の HTML は逃がしているが、`[文字](URL)` の URL の種類（スキーム）を確かめていないため、スクリプトを実行する種類の URL のリンクが作られ、押した人の画面でスクリプトが動く | URL を `http:`・`https:` だけに限る（それ以外はリンクにしない） |
| B7 | 認可の抜け（編集） | `src/app/api/comments/[commentId]/route.ts` の `PATCH` | 削除（`DELETE`）は投稿者かを確かめるが、編集（`PATCH`）は確かめない。ログインした誰でも、他人のコメントを書き換えられる | 投稿者でなければ 403 にする |
| B8 | 存在しないタスクへの追加 | `src/app/api/tasks/[id]/comments/route.ts` の `POST` | タスクがあるかを確かめずに追加するため、存在しない ID では外部キーの制約で例外になり 500 になる（`GET` は 404 を返すのに揃っていない） | 追加の前に `getTask(id)` で確かめ、無ければ 404 |
| B9 | 日時の保存形式と並び | `src/lib/comments.ts` の `formatCreatedAt`・`listComments`（`ORDER BY created_at`） | 作成日時を表示用の文字列（`2026/11/11 9:00:00`）で保存し、文字列で並べているため、`9:00` が `10:00` より後になるなど、古い順にならない（桁数の違う時・日・月で崩れる） | ISO 8601（UTC）で保存して並べ、表示するときに日本時間に直す |

### おとり（不具合ではない変更。指摘したら誤った指摘）

| ID | 場所 | 見た目 | 正しい理由 |
|---|---|---|---|
| D1 | `src/lib/week.ts` の `todayJst`（`Intl.DateTimeFormat("sv-SE", { timeZone: "Asia/Tokyo" })`） | ロケールに `sv-SE` を使っている | `sv-SE` の形式が `YYYY-MM-DD` になるための定番の書き方で、時差も日本時間で正しく扱っている |
| D2 | `dueThisWeek` が期限切れ（今週の月曜〜昨日）のタスクも含む | 期限切れと重複する | 「今週が期限」の範囲に入るので含めてよい（仕様の選択。誤りではない） |
| D3 | コメントの表に `ON DELETE` が無い | タスクを消すとコメントが残る・消せない | このアプリにはタスクの削除が無い。今は問題にならない |
| D4 | `renderBody` の `escapeHtml` が `'` を逃がしていない | 属性で XSS になる | 属性はダブルクォートで囲んでおり、`'` では抜けられない（問題は B6 の URL の種類） |

- 一致の基準: 場所（ファイルと関数）と仕組みの核心の両方を述べていれば一致。B6 は URL の種類（スキーム）を確かめていないことを述べていれば一致（「`dangerouslySetInnerHTML` は危ない」だけの一般論は一致にしない）。
- PR の説明は短く、要件は書いていない。どの不具合も、説明が無くても誤りと言えるものだけを正解にした。
