# PR: 西日本校正センターの CSV を校正記録として取り込めるようにする

## 依頼

校正機関 B 社（西日本校正センター。12 月から契約）の新しい CSV 形式でも、校正記録を取り込めるようにしてほしい（A 社 = 東日本計測サービスは今までどおり続く）。

## 合意した要件（依頼者との確認で決まったこと）

1. 形式は B 社の仕様書（`docs/agencies/nishinihon-csv-spec.md`）とサンプルのとおり。B 社の校正記録の校正機関は「西日本校正センター」とする。
2. どちらの会社の CSV かを担当者に選ばせない。今と同じ送り先（`POST /api/calibrations/import`）で、どちらの形式も入る。月初にスクリプトから CSV をそのまま送っている。
3. 形式は取り込むときに自動で見分ける。ファイルの保存のしかた（BOM の有無・改行コード）の違いで取り込めなくならないようにする。
4. 「COND」（条件付き合格）は合格として取り込み、その計測器の備考の末尾に「条件付き合格（校正日）: コメント」を書き足す。「有効期限」の列は使わない。
5. B 社の機器番号はハイフン無し（MI0003）で来ることがある。A 社と同じく同じ計測器として扱う。
6. 最後の「END,件数」と実際の行数が合わないファイルは 1 件も取り込まない（転送が途中で切れたことがある）。
7. 同じファイルを 2 回取り込んでも二重にしない。同じファイルの中の重複も、A 社と同じ決まりで後の行を読み飛ばす。
8. 台帳に無い機器番号・読めない判定の行は誤りにして、ほかの行は取り込む（件数の不一致だけはファイル全体を止める）。
9. 取込の応答の形（imported・skipped・errors と各要素の line）は変えない。
10. A 社の取込は今までどおり（和暦・○×・保留・参考の読み飛ばしなど）。過去 3 年分を監査で取り込み直すことがある。

## 変更内容

- 校正記録の登録と同時に、計測器の備考へ書き足せるようにする
- 西日本校正センターの CSV を同じ送り先で取り込む（見出しで見分ける）
- 全角変換の重複をまとめ、判定の型を既存の型にそろえる
- 備考がいっぱいでも条件付き合格の印を残し、1000 文字を超えないようにする
- 取込の手順書の、備考が満杯のときの扱いを実装に合わせる

## 検証結果

- `npm run typecheck`・`npm test`・`npm run build` が通ることを確認した。
