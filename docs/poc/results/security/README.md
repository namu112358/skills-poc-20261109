# セキュリティ監査の PoC の結果（PLAN §5.2）

実施日: 2026-11-11。実行と採点: Claude Code（無人。PLAN の「採点者 2 名」は満たしておらず、採点者は 1 名）。
題材と正解は `docs/poc/answer-key/SEC/answers.md`、試行のスクリプトは `scripts/poc/run-security-trial.sh`、生の記録は `raw/`（git には入れない）。

## 結論

- **全体の監査は、Claude Security（medium）が、Cloudflare Security Audit（standard）より安く速く、結果もそのまま使える。**
  - 見つけた数は同じ。既知の脆弱性 12 件を、どちらもすべて挙げた。
  - 費用と時間は、Claude Security が $10.52・24 分、Cloudflare が $39.44・45 分。
  - Claude Security は、12 件すべてを確認済みにし、深刻度も付けた。Cloudflare は確認済みが 0 件で、すべて「要確認」のまま深刻度が付かなかった。
- **Cloudflare は、この環境では指摘を「確認済み」にできない。** 確認済みにするには、対象のコードを OS の機能で隔離して動かす必要があるが、クラウドのセッションでは隔離の手段を用意できなかった。そのため、すべての指摘が「要確認」のままになる。
- **Cloudflare は、Sonnet 5.5 では動かない。** 探索役のエージェントが、すべて安全機構（`general_harms`）に止められた。Opus 5.5 では止められなかった。
- **PR ごとの差分の監査は、ふだんは `/security-review`、認証・セッション・権限に触れる PR は Claude Security の差分スキャンがよい。** 差分の中で完結する脆弱性は、`/security-review` が $1 前後・2 分で、すべて見つけた。既存のコードと合わせて初めて分かる脆弱性（SEC-3）では、`/security-review` が 3 件中 1〜2 件にとどまり、Claude Security（$2.6〜2.8）は 2 回とも 3 件すべてを見つけた。
  - Claude Security（medium）も 3 件すべてを挙げた（$2.44・5 分）。
  - Cloudflare（quick）も 3 件すべてを挙げたが、すべて「要確認」で、$9.57・20 分かかった。
- **この題材は易しすぎて、見つけた数に差が出なかった。** 見つけにくい脆弱性の差分で比べ直した（SEC-2）が、それでも差は出なかった。差分の中だけで完結する脆弱性は、どのツールでも見つかる。差が出たのは、既存のコードと合わせて初めて分かる脆弱性（SEC-3）だった。

モデルは、Sonnet 5.5 と書いた行を除いて Opus 5.5。費用は Claude Code が出した `total_cost_usd`（親とサブエージェントの合計）。

### 深刻度のずれ（vulns）

| ID | 正解 | Claude Security | Cloudflare |
|---|---|---|---|
| V6 ヘッダーを信じる認可 | high | medium（1 段低い） | なし（要確認） |
| V9 Webhook の署名の確認のすり抜け | critical | medium（2 段低い） | なし（要確認） |
| V11 一括代入と列名の SQL インジェクション | critical | high（1 段低い） | なし（要確認） |
| ほかの 9 件 | — | 正解と同じ | なし（要確認） |

Cloudflare は、V8（Cookie の HttpOnly の無効化）を単独では挙げず、V2（保存型 XSS）の指摘の中で一緒に扱った。この表では、見つけた数に含めている。

### 観察

- **Cloudflare は、隔離を自分で用意しようとした。** OS の隔離の手段（bwrap など）やマウントを調べるコマンドを実行しようとし、許可していないので止められた。そのあとは、コードを読むだけで判断した。Skill の決まりどおりの動きで、要確認には「隔離して動かせば確かめられる」という確かめ方が付いている。
- **どのツールも、対象のソースを書き換えなかった。** 試行の後に作業用コピーを確かめた。
- **許可していないコマンドで止められた回数**: Cloudflare は 1 回の試行で 6〜20 回。複数のコマンドをつないだものや `git -C` が多く、どれも止められたあとに別のやり方で続けた。

## SEC-2: 見つけにくい脆弱性の差分（PR ごとの監査の選定）

PR ごとの監査の候補（安い 2 つ）を、1 か所を読むだけでは分からない脆弱性 3 件と、誤検知の罠 2 件を含む差分（diff2）で比べた。題材ごとに 2 回ずつ回した。モデルは Opus 5.5。

| ツール | 回 | 見つけた数 | 誤検知 | 深刻度のずれ | 費用 | 時間 |
|---|---|---|---|---|---:|---:|
| `/security-review` | 1 | 3 / 3 | 0 | なし | $1.24 | 2 分 |
| `/security-review` | 2 | 3 / 3 | 0 | なし | $1.12 | 2 分 |
| Claude Security（medium） | 1 | 3 / 3 | 0 | H3（パスワードのハッシュの漏えい）を medium にした（正解は high） | $2.56 | 4 分 |
| Claude Security（medium） | 2 | 3 / 3 | 0 | 同上 | $2.23 | 5 分 |

- **見つけにくくしても、差は出なかった。** どちらのツールも、2 回とも 3 件すべてを挙げた。罠（推測できないトークン、値を逃がした URL）にはどちらも反応しなかった。
- **期限切れの判定の誤り（H2）は、正解リストより正確だった。** 正解リストでは「いつまでも期限切れにならない」としていたが、どちらのツールも「年が変わるまで切れない」と指摘し、こちらが正しかった。正解リストを直した。
- **PR ごとの監査には `/security-review` で足りる。** 費用は Claude Security の約半分で、深刻度も正解とずれなかった。ただし、差分が数ファイルに収まる題材でしか確かめていない。

## SEC-3: 既存のコードと合わせて初めて脆弱性になる差分

SEC-2 でも差が出なかったため、差分だけを読んでも判断できず、差分の外の既存のコードと突き合わせて初めて分かる脆弱性 3 件と、同じく既存のコードを読まないと安全と分からない罠 2 件の差分（diff3）で比べた。2 回ずつ回した。

| ツール | 回 | E1 ハッシュの漏えい（high） | E3 ユーザーの有無（medium） | E2 ログアウトの CSRF（low） | 誤検知 | 費用 | 時間 |
|---|---|---|---|---|---|---:|---:|
| `/security-review` | 1 | ○（medium） | × | × | 0 | $1.09 | 2 分 |
| `/security-review` | 2 | ○（high） | ○（medium） | × | 0 | $1.16 | 2 分 |
| Claude Security（medium） | 1 | ○（medium） | ○（medium） | ○（low） | 0 | $2.77 | 5 分 |
| Claude Security（medium） | 2 | ○（medium） | ○（medium） | ○（low） | 0 | $2.58 | 5 分 |

括弧の中は、ツールが付けた深刻度。

- **初めて差が出た。** Claude Security は 2 回とも 3 件すべてを見つけた。`/security-review` は、2 回で 1 件と 2 件で、低い深刻度の E2 は 2 回とも挙げなかった。
- **`/security-review` は、回によって結果が変わった。** E3 は 2 回目だけ見つけ、E1 の深刻度も回によって違った。
- **罠には、どちらも反応しなかった。** 外部キーが守っている付け替え（T6）と、id と名前しか返さない取得（T7）は、どちらのツールも指摘しなかった。
- **PR ごとの監査の推奨を改める。** ふだんの PR は `/security-review`（約 $1）で足りるが、認証・セッション・権限に触れる PR は、Claude Security の差分スキャン（約 $2.7）を使う。費用の差は 1 回 $1.5 ほどで、見落としを減らせる。

## 費用

この PoC で使った額の合計は、SEC-1 が $95.0、SEC-2 が $7.15、SEC-3 が $7.59。
Cloudflare の standard は、規模の小さい `poc-app`（約 1,300 行）でも、1 回 $15〜40 かかった。
