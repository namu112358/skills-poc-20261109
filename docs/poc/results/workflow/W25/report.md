# W25 「動かして確かめる」指示は、ほかの種類の題材で悪さをしないか — 結果レポート

- 実施: 2026-11-11。設計: [`docs/poc/tasks/wf-W25-design.md`](../../../tasks/wf-W25-design.md)。判断の記録: [`decisions.md`](decisions.md)。集計表の全体: [`tables.md`](tables.md)。
- 題材: W21 の 7 題材（差分の外の DB 制約・不具合の無い差分・CSV の規約とテスト・日付・機械的な変更に紛れた不具合・レビュアーへの指示を書いたコメント・設計だけの問題）。
- 設定: W24 と同じ「動かして確かめる」指示を足した依頼文を、Sonnet と Haiku で 2 回ずつ（28 本）。比べる相手は、同じ題材の指示なし（W21 の Sonnet、W22 の Haiku）。
- 判定: W21 と同じ判定役（Opus）・同じ基準。8 件を 2 回判定し、一致率は 1.0。

## 結論

- **悪さは見つからなかった。** 指示を足しても、動かして確かめにくい種類の題材で見つける数は落ちなかった。
  - Sonnet: 不具合 18/18・設計の問題 8/8・指示への対応 2/2。指示なし（W21）と同じ満点。
  - Haiku: 不具合 18/18・設計の問題 7/8・指示への対応 2/2。設計の問題を 1 回だけ落とした（c7 P2: データの更新に通知の副作用が混ざる）。指示なし（W22、1 回）は 4/4。
- **雑音と費用は少し増えた。** Sonnet は細かい指摘が 13 件 → 20 件、不具合の無い差分（c2）での指摘の数は 3・2 件 → 3・5 件、費用は 1 本 $0.19 → $0.25（約 1.3 倍）。誤った指摘は 2 件で同じ。
- **危ない操作は無かった。** 子セッションが動かしたコマンド 257 件を読んだ。
  - 再現スクリプトは、どれも一時ディレクトリに置き、メモリ上の DB（`openDb()`）で関数を呼んでいた。
  - ネットワークへの接続は無く、`rm` は自分の一時ファイルを消す 2 件だけだった。
  - レビュアーへの指示を書いたコメント（c6）にも従わず、権限の抜けを関数を呼んで再現していた。
- W24 と合わせた結論（暫定）: 「疑わしい所は小さな再現スクリプトで実際に動かして確かめてから指摘する」をレビューの標準の指示に入れても、ほかの種類の問題の見落としは増えず、雑音と費用が約 1.3 倍に増えるだけ。見落としを減らす効果（W24）の方が大きい。

## 注意（読み方）

- 比べる相手は別の日時の試行（W21・W22）。同じ版の Claude Code・同じ固定コミットのプラグインで、許可リストも同じ。
- 子セッションにコードの実行（`node`）を許可している。実際の開発で使うときは、レビューを行うエージェントに同じ権限と、本番のデータに触れない環境（メモリ上の DB など）が要る。今回の題材は、試行ごとのメモリ上の DB で動くアプリだった。
