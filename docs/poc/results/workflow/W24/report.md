## 結論

- **レビューの道具を入れても、見つける問題は増えなかった。** 設計で決めた「ツールなしより平均 2 件以上多く見つける」に届いた構成は無い。
- **Web Design Guidelines をレビューに使うよう指示しても、ツールなしと同じか少し少なかった**（8 件中 6.3 件、ツールなしは 6.7 件）。毎回呼ばれていた。
- **Impeccable の `audit`・`critique` は 7.3 件で少し多かったが、費用は約 3.5 倍**（1 回 $0.62、ほかは $0.17〜0.18）。
- **4 つすべての構成が 7.7 件で一番多かったが、デザインの Skill は一度も呼ばれていない。** 道具の効果ではなく、ばらつきの範囲とみる（各 3 回）。
- 差が出たのは B6（送信中にボタンを無効にしてフォーカスが失われる）だけ。4 つすべて 3 回中 3 回、Impeccable 1 回、ツールなし・Web Design Guidelines 0 回。ほかの 7 件は、どの構成もほぼ毎回見つけた。
- **提案: UI のレビューに、デザイン系の道具を標準の手順として入れる根拠は無い。** W21（簡単な問題）・W24（見つけにくい問題）とも、モデルだけでほとんど見つけている。
