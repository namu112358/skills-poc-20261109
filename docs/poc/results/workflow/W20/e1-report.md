# E1 Feature Dev → Superpowers の置き換えの確認 — 結果レポート

- 実施: 2026-11-10。判断の記録: [`decisions.md`](decisions.md)（代理人の判断 E-D1・E-D2）。
- 方法: これまで Feature Dev が上だった W3（要件があいまい）・W14（DB 移行）と、W19（粗悪な既存実装）で、今の版の Claude Code・Skills で 3 回ずつ流して比べた。過去の 2 回は版が違うので、参考に並べるだけにした。

## 結論

- **実装・移行の場面では、置き換えてよい。** W14・W19 では、品質の差が 3 回の幅の中に収まった（差なし）。費用は Superpowers のほうが安い（W14 で約半分）。
- **要件があいまいな場面では、今の版でも Feature Dev が上。** W3 は Feature Dev 89.8・Superpowers 73.1 で、差（16.7 点）は 3 回の幅より大きい。過去の 2 回（89.4 対 73.2）とほぼ同じ。Superpowers の brainstorming は 1 問ずつ背景を深掘りし、隠れ要件（期限が近いもの・件数から一覧へなど）を聞かないまま要件をまとめた。
- 開発フローへの反映（提案）: normal は Superpowers に置き換える。ただし要件があいまいなときの「計画（要件を詰める）」の段は、最初に観点を広く並べて聞かせる（Feature Dev の質問の段か、brainstorming に「最初に観点を網羅して聞く」を指示する）。
