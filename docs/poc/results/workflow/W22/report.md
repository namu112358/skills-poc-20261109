# 開発ワークフロー PoC — W22 デザインの Skill を CLAUDE.md で指定したときの効果

実施日 2026-11-11 ・ モデル claude-sonnet-5-5 ・ Claude Code 2.1.322 ・ 設計 [docs/poc/tasks/wf-W22-design.md](../../../tasks/wf-W22-design.md)

> **暫定の報告です。** 見た目の評価は補助の AI の判定（`claude-opus-5-5`）によるものです。依頼者の順位付けが付いたら確定させます。試行の結果は W21 と同じ場所（`results/workflow/W21/`）にあり、試行 ID は `W21<課題>-<構成>-<回>` です。

## 結論（暫定）

- **`CLAUDE.md` に「画面を作るときはこの Skill を使う」と書くと、指定した Skill が毎回呼ばれた**（3 構成とも 9 回中 9 回）。書かないときは、同じ題材で 58〜92% だった。
- **呼ばれるようになると、AI の見た目の判定も上がり、費用はむしろ下がった。**
  - Frontend Design: 15.4 → 16.5 点、$0.79 → $0.59。
  - Impeccable: 14.5 → 15.8 点、$1.43 → $1.12。
  - Skill を探して迷う手間が減ったためとみられる（未確認）。
- **4 つすべてを入れたまま役割を割り振っても、評価は上がらなかった**（14.4 → 14.4 点）。費用は $0.72 → $1.20 に増えた。
  - 割り振りどおり Impeccable が毎回呼ばれ、Web Design Guidelines も 9 回中 4 回呼ばれた。
  - それでも、同じ Impeccable を使う「Impeccable + 指示」（15.8 点）より低かった。
- **提案（暫定）: 標準は「Frontend Design + Web Design Guidelines」にし、各プロジェクトの `CLAUDE.md` に使う Skill を書く。** Impeccable と UI/UX Pro Max は既定では入れない。Impeccable は、宣伝のページなど見た目に力を入れる案件で、使う人が足す。

- 機械の検査（機能・axe・幅 375px）は、どの構成も 50 点中 48〜50 点で差がない。

## AI の判定の安定性（重要）

W21 の 20 試行を判定した後、W22 の 9 試行を加えて同じ 20 試行を判定し直すと、点が動いた。

| 題材 | 1 回目と 2 回目の相関 | 最大の差 |
|---|---:|---:|
| SaaS の LP | 0.48 | 3.5 点 |
| ダッシュボード | 0.85 | 1.5 点 |
| 登録フォーム | 0.87 | 2.5 点 |

- 1 回の判定の中で順番を変えた 2 回は、ほぼ一致する（差は 0〜3 点）。しかし、一緒に並べる画面が変わると点が動く。
- W21 の暫定の報告にあった「宣伝のページでは Impeccable が一番高い」は、判定し直すと成り立たなかった（SaaS の LP で Impeccable は 15.9 → 14.6 点、Frontend Design は 14.9 → 17.5 点）。
- そのため、構成どうしの 1〜2 点の差は判断に使わない。上の結論は「指示ありの方が、Frontend Design・Impeccable の両方で、3 題材すべてで点が同じか上」という向きのそろいを根拠にしている。依頼者の順位付けで確かめる。
- 次の W23 からは、同じ試行の前後を比べる「対の比較」に切り替えた。

## 判断の記録

- W22 は、W21 の途中の結果（4 つすべてのとき Skill が呼ばれない）を受けて、依頼者の不在の間にコーディネーターが立てた。
- 指示の文面は `docs/poc/tasks/wf-W22-<構成>.md` に固定した。試行の作業用コピーのアプリの `CLAUDE.md` の末尾に足している。
- 実行中のスクリプトを書き換えるときは、新しいファイルに書いて置き換える形にした。W21 で、実行中のスクリプトを書き換えて処理が止まったため。
