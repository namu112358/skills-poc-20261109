# 要件: チーム進捗の可視化

## 1. 背景と目的

- 依頼者: 佐藤さん(チームリーダー)。主な利用者は佐藤さん。メンバーも閲覧してよい。
- 課題: 毎週の定例で各自に口頭で状況を聞いている。タスク一覧は全件が並ぶだけで、「誰がどれだけ抱えているか」「どれが遅れているか」がひと目で分からない。
- 目的: 定例で遅れているタスクを早く見つけて手を打てるようにする。口頭での聞き取りを減らす。
- 方針: メンバーの入力の手間を増やさない。既存のステータスと期限だけで分かるようにする(例外として、完了日時のみ自動記録する)。

## 2. 優先順位と提供時期

| 優先 | 内容 |
| --- | --- |
| 1(最優先) | 期限切れタスクの表示(3.1) |
| 2 | 担当者別の件数表(3.2)、担当者での絞り込みと件数からの遷移(3.3) |
| 3 | 完了日時の記録と、今週の完了数(3.4) |

- 2 週間以内に最初の版を使い始めたい。まずは最低限とし、足りなければ後で足す。
- 優先 1 だけで使い始められるようにする。

## 3. 機能要件

### 3.1 期限切れ・期限間近のタスク(最優先)

- 画面の上部に、期限切れを最も目立つ形で表示する。
- 期限切れの定義: 期限が今日より前で、ステータスが「完了」ではないタスク。
- 表示内容:
  - 期限切れの件数
  - タスクの一覧(タイトル、担当者名、期限、期限から何日過ぎたか)
  - 並び順: 過ぎた日数が多いものを先頭にする。同じ日数なら ID 順。
- 期限切れとは別に、「7 日以内に期限が来る未完了タスク」を表示する。
  - 範囲は今日を含めて 7 日間(今日から 6 日後まで)。期限切れは含めない。
  - 件数と一覧(タイトル、担当者名、期限、あと何日か)を出す。
  - 並び順: 期限が近いものを先頭にする。
- 該当が 0 件のときは、「期限切れのタスクはありません」のように明示する。

### 3.2 担当者別の件数表

- 担当者ごとに、未着手・進行中・完了の件数を表にする。担当者は名前(佐藤など)で表示する。
- 全タスクが対象。タスクが 0 件の担当者も行を出す。
- 列: 担当者、未着手、進行中、完了、合計、完了率、今週完了。
  - 完了率は 完了 ÷ 合計(合計 0 のときは「-」)。整数の % で表示する。依頼者から「お任せ」とされた項目。
  - 今週完了の定義は 3.4 を参照。
- 最下行に全体の合計を出す。

### 3.3 絞り込みと遷移

- 3.2 の表の件数(未着手・進行中・完了・合計)をリンクにし、クリックすると「その担当者・そのステータス」で絞り込んだタスク一覧(`/tasks`)へ移る。合計は担当者のみで絞り込む。
- タスク一覧に、担当者での絞り込みを追加する(クエリ `assignee`)。
  - 既存の表示とステータスでの絞り込みは変えない。両方を同時に指定できる。
  - 画面には担当者の選択欄を追加する。値は、存在するユーザー ID か検証する。不正な値は「指定なし」として扱う。
- API の `GET /api/tasks` にも、同じ `assignee` の絞り込みを追加するかは設計時に決める(既存の挙動は変えない)。

### 3.4 完了日時の記録と「今週完了」

- タスクに完了日時(`completed_at`)を持たせる。
  - ステータスが「完了」になったときに自動で記録する(画面・API のどちらから変更しても)。
  - 「完了」から別のステータスに戻したら、記録を消す。
  - 完了のまま他の項目だけを更新した場合は、記録を変えない。
  - 完了状態で新規作成した場合は、作成時刻を記録する。
- 過去の完了済みタスクは埋めない(記録は開始後のみ)。そのため、導入前に完了したタスクは「今週完了」に数えない。
- 「今週」は日本時間(JST)の月曜 0:00 から日曜 24:00 までとする。月曜始まりは依頼者に確認済み。
- 作成日時・更新日時は、今回は追加しない(依頼者から「お任せ」とされた項目。必要になった時点で追加する)。

### 3.5 日付の扱い

- 「今日」「期限切れ」「7 日以内」「今週」の判定は、すべて日本時間(JST)の日付で行う。サーバーのタイムゾーンに依存させない。
- 判定に使う「現在時刻」は関数の引数で渡せるようにし、テストで固定できるようにする。

### 3.6 アクセス制御

- ログイン済みのユーザーなら誰でも、全員分を見られる。
- 未ログインには見せない。画面はログイン画面へ移し、API は 401 を返す。

### 3.7 画面の置き場所

- 新しい画面(例: `/dashboard`)として追加し、トップ(`/`)の移動先もそこにするかは設計時に決める。既存の `/tasks` と `/tasks/:id` は残す。
- 画面の文言は日本語にする。

### 3.8 API

- 依頼者は「お任せ」。画面と同じ集計を JSON で返す読み取り専用の API(例: `GET /api/summary`)を追加する方針。
- ただし画面が最優先であり、時間が足りなければ API は後回しにしてよい。
- 追加する場合は既存規約に従う(最初にログイン確認、エラーは `{ error, details? }`)。

## 4. 範囲外

- メール、Slack などの通知
- 進捗率(%)や工数の入力
- グラフ、ガントチャート、バーンダウンチャート
- 過去からの推移(先週との比較など)
- 看板(カンバン)形式の表示
- 更新履歴(いつ・誰が何を変えたか)の表示・記録(完了日時を除く)
- 過去の完了日時の埋め戻し
- 権限管理(閲覧範囲の制限)
- 新しい外部ライブラリの追加

## 5. 非機能・制約

- 既存の規約に従う(`CLAUDE.md` のコーディング規約)。
  - データの取得・集計は `src/lib/` の関数に置き、ページには表示の処理だけを書く。
  - スキーマ変更は `migrations.ts` の末尾に新しい番号(3)で追加し、既存のマイグレーションは書き換えない。
  - SQL は必ずプレースホルダを使う。
  - ロジックを追加・変更したら `tests/` に単体テストを追加する。
- 表と数字だけで表現する。グラフ描画は行わない。
- 変更は依頼された範囲にとどめる。

## 6. 受け入れ条件

1. ログインして画面を開くと、期限切れの件数と一覧(担当者・期限・過ぎた日数)が最上部に出る。
2. 期限が今日のタスクは期限切れに含まれず、「7 日以内」に含まれる。期限が昨日で未完了のタスクは期限切れに含まれる。期限が昨日で完了済みのタスクは、どちらにも含まれない。
3. 期限が今日から 6 日後のタスクは「7 日以内」に含まれ、7 日後のタスクは含まれない。
4. 担当者別の表に、全担当者(0 件の人も)の未着手・進行中・完了の件数が名前つきで出る。
5. 表の件数をクリックすると、担当者とステータスで絞り込まれたタスク一覧に移る。一覧の担当者の絞り込みを変えても、既存のステータス絞り込みは今までどおり動く。
6. ステータスを完了にすると完了日時が記録され、完了から戻すと消える。今週完了の数は、JST の今週に記録された完了だけを数える。
7. 未ログインでは画面も API も見られない(画面はログインへ、API は 401)。
8. `npm run typecheck` と `npm test` が通る。日付の境界(JST の日付またぎ、月曜の切り替わり)のテストがある。

## 7. 未確認・設計時に決めること

- 「今週」は月曜〜日曜で確定(依頼者に確認済み)。導入前に完了したタスクを数えない点も確認済み。
- 新画面の URL と、トップ(`/`)の移動先。
- `GET /api/tasks` に `assignee` を足すか。集計 API を今回入れるか。
- 完了率・「最近何が動いたか」の見せ方は「お任せ」。最近の動きは、今週完了した数と完了日時で代替し、専用の表示は作らない。
