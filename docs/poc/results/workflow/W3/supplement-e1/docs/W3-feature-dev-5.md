# 要件: 進捗画面

## 背景・目的

チームの進捗が見えにくい。主な利用者はリーダーで、定例で「遅れているタスク」を早く見つけて手を打ちたい。ログインしているメンバー全員が見てよい。
メンバーの入力の手間は増やさず、既存のステータスと期限だけで分かるようにする。

## スコープ

### 1. 「進捗」画面（新規）

- パスは `/progress`。ヘッダーに「進捗」リンクを追加する（ログイン時のみ表示）。
- 数字と表だけで表示する。グラフ、ガントチャート、新しい外部ライブラリは使わない。
- ログイン必須。未ログインは `/login` へ（既存ページと同じ `requireUser()`）。ログインしていれば全員分を表示する。
- 画面の文言は日本語。

#### 1-1. 期限切れ（最も目立たせる）

- 定義: 期限が今日（JST）より前で、ステータスが完了ではないタスク。
- 画面の最上部に件数を大きく表示し、その下に一覧を出す。
- 一覧の列: タイトル（詳細へのリンク）、担当者（名前）、期限、何日過ぎたか（例: 「3日超過」）。
- 並び順: 超過日数が多い順。
- 0 件のときは「期限切れのタスクはありません」と表示する。

#### 1-2. 期限が近い（期限切れとは別枠）

- 定義: 期限が今日を含めて 7 日以内（今日〜今日+6日、JST）で、未完了のタスク。
- 期限切れとは別の見出し・表で表示する。
- 一覧の列: タイトル、担当者（名前）、期限、あと何日か（今日が期限なら「今日」）。
- 並び順: 期限が近い順。
- 0 件のときはその旨を表示する。

#### 1-3. 担当者別の件数

- 行は担当者（表示は「佐藤」などの名前）。列は未着手・進行中・完了の件数、および今週完了した数。
- タスクが 0 件の担当者も行を出す。
- 件数（未着手・進行中・完了）はリンクで、その担当者・そのステータスで絞り込んだタスク一覧（`/tasks?assignee=<ID>&status=<ステータス>`）へ移動できる。0 件のセルはリンクにしなくてよい。

#### 1-4. 今週の完了数

- 担当者ごとに表示する（1-3 の表の列）。
- 「今週」は日本時間（JST）の月曜 0:00 から、次の月曜 0:00 の直前まで。
- 完了日時が記録されているタスクだけが対象。

### 2. タスク一覧の担当者絞り込み（追加）

- `/tasks` にクエリ `assignee`（ユーザー ID）を追加する。既存の表示とステータス絞り込みは変えない。
- 担当者の絞り込み用セレクトを、既存のフォームに追加する（「すべて」＋ユーザー名）。
- 存在しない ID、または不正な値は「指定なし」として扱う（型ガードで検証する）。
- `listTasks` の `TaskFilter` に `assignee` を追加する。API の `GET /api/tasks` の扱いは今回は変えない。

### 3. 完了日時の記録（スキーマ変更）

- `tasks` に `completed_at`（UTC の ISO 8601、NULL 可）を追加する。新しいマイグレーション（version 3）を末尾に足す。既存のマイグレーションは書き換えない。
- ステータスが完了になったとき（作成時に完了で作る場合も含む）に、現在時刻を記録する。
- 完了から別のステータスに戻したら、記録を消す（NULL）。
- すでに完了のタスクを完了のまま更新（タイトル変更など）しても、記録は変えない。
- 過去の完了分は埋めない（`completed_at` が NULL のまま）。今週の完了数には含まれない。
- 初期データ（seed）の完了タスクにも、デモ用に今週内の完了日時を持たせるかどうかは実装時に決める。ただしマイグレーションでは埋めない。
- 記録は `createTask` / `updateTask`（`src/lib/tasks.ts`）の中で行い、API と画面の両方で同じ挙動にする。

### 4. 日付の判定

- 「今日」は JST の日付で判定する。判定は `src/lib/` の関数で、基準時刻を引数で渡せるようにして単体テストする。
- 期限（`due_date`）は `YYYY-MM-DD` の日付として比較する。

## スコープ外

- 通知（メール、Slack など）
- 過去からの推移、先週との比較
- 進捗率、工数の入力
- グラフ、ガントチャート、新しい外部ライブラリ
- 過去の完了分の補完
- CSV 出力（依頼者から「お任せ」の回答があり、不要と判断してやらない）
- 集計用の API（画面だけで足りる。API はお任せの回答で、追加しない）
- 既存のタスク一覧の表示変更、ステータス絞り込みの変更

## 実装方針（制約）

- 集計・絞り込みは `src/lib/`（例: `src/lib/progress.ts`）に置き、ページは表示だけを書く。
- SQL は必ずプレースホルダを使う。
- `tests/` に単体テストを追加する。対象は期限切れ、7日以内の判定、JST の境界(日付またはその週の境目)、今週の完了数、担当者別の件数、完了日時の記録と消去、担当者絞り込み、マイグレーション。
- `npm run typecheck` / `npm test` / `npm run build` が通ること。

## 受け入れ基準

1. ログインして `/progress` を開くと、期限切れ、期限が近いタスク、担当者別の件数と今週完了数が見える。ヘッダーから行ける。
2. 未ログインで `/progress` を開くと、ログイン画面へ移動する。
3. 担当者別の件数をクリックすると、その担当者・ステータスで絞り込まれた `/tasks` が開く。
4. `/tasks` の既存の表示とステータス絞り込みは変わらず、担当者でも絞り込める。
5. タスクを完了にすると完了日時が記録され、戻すと消える。今週完了した数に反映される。
6. 期限が今日のタスクは、期限切れにならず「期限が近い」に入る。昨日が期限の未完了タスクは期限切れに入る。
