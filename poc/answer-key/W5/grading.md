## 配点（100 点。PLAN.md §5.1）

| 観点 | 配点 | 測り方 |
|---|---|---|
| 根本原因を正しく直せた数 | 50 | バグ 1 件ごとに 50/3 点。下の「直せた」の条件を満たしたバグの数で決める |
| 回帰テストの追加 | 25 | バグ 1 件ごとに 25/3 点。下の「回帰テストがある」の条件を満たしたバグの数で決める |
| 既存テストの維持 | 10 | 10 ×（元からある単体テストのうち、試行のコードで通った数 / 総数）。候補自身の `npm test` が失敗していれば半分にする |
| 所要時間 | 15 | 15 ×（W5 の全試行の最短の所要時間 / 自分の所要時間）。所要時間は `run-trial.sh` が測る壁時計の時間（`elapsed-seconds`） |

- 正解データ（`poc/answer-key/`）を読んだ形跡がある試行は、根本原因と回帰テストを 0 点にする（`grade.py` の `answer_key_access`）。
- 介入（定型の「お任せします」で続けさせた回数）・質問・権限の拒否は点数に入れず、レポートに記録する。

### 「直せた」の条件（`grade_w5.py`）

次の 2 つを両方満たしたとき、そのバグを根本原因から直せたとする。

1. **報告の症状が消えた**: 隠しの E2E（`acceptance.cjs`）で、そのバグの番号（`[B1]` など）が付いたチェックがすべて通る。サーバーは `npm run build` → `next start` で起動したばかりの状態。
2. **原因の層で直っている**: 隠しの単体テスト（`hidden.test.ts`）で、そのバグの番号のテストが通る。`src/lib/` の既存の関数（`validateTaskInput`、`createSession` / `getSessionUser`、`listTasks` / `updateTask`）を直接呼ぶ。
   - 例: B3 を画面の側（`export const dynamic = "force-dynamic"` など）や API Route の側だけで手当てしても、`src/lib/` の一覧と更新の食い違いは残るので「直せた」に数えない。B2 を Cookie の側だけで手当てした場合も同じ。

E2E の 1 だけ通ったバグは「症状だけ」としてレポートに記録する（点数は 0）。`[既存]` のチェックは点数に使わず、修正で既存の動作を壊していないかの記録にする。

### 「回帰テストがある」の条件（`grade_w5.py`）

候補が `tests/` に追加・変更したテストファイルを、次の 2 種類のコードで実行する。

- 参照用のコード: `poc-app` + `bugs.patch` + 正解の修正 3 件（`fix1〜3.patch`）
- バグを 1 つだけ戻したコード: 上から、そのバグの修正だけを外したもの

参照用のコードでは通り、バグを戻すと落ちるテストが 1 件以上あれば、そのバグの回帰テストがあるとみなす。

- 候補が新しく作った関数を import しているなどで、参照用のコードでテストが動かない場合（`ref_failures`）は、採点者がテストの中身を読んで判断し、判断と理由をレポートに書く（`notes.json` の `regression_override`）。

- `poc-app`（main）: 型チェック・単体テスト（19 件）・ビルドが通り、隠しの E2E 8 件・隠しの単体テスト 3 件がすべて通る。
- `poc-app` + `bugs.patch`: 型チェック・単体テスト（19 件）・ビルドは通る。隠しの E2E は `[B1]` 2 件と `[B3]` 3 件が落ち（`[B1]` の 201 文字、`[B2]` の Cookie、`[既存]` は通る）、隠しの単体テストは 3 件とも落ちる。
- `poc-app` + `bugs.patch` + `fix1〜3.patch`: 隠しの E2E 8 件・隠しの単体テスト 3 件がすべて通る。

## 2 本立ての点数（2026-11-09 追加。試行後に追加した並記用の計算）

上の配点による点数（総合点）と順位は変えず、同じ採点結果から「品質」と「効率」の 2 本の点数を並記する（定義は [PLAN.md §4.4](../../PLAN.md)）。

- 品質（100 点）=（根本原因 50 + 回帰テスト 25 + 既存テストの維持 10）÷ 85 × 100。「所要時間」15 点は品質に入れない。
- 効率（100 点）= 費用 50 + 時間 30 + 介入 20。費用・時間は W5 の baseline の実額・壁時計の時間（`elapsed_seconds`）に対する倍率で、2 倍以下 = 満点、3 倍以下 = 80%、5 倍以下 = 60%、10 倍以下 = 30%、10 倍超 = 0。介入（定型の「お任せします」の回数）は 0 回 = 20、1 回 = 10、2 回以上 = 0。
- 質問の回数は効率から引かない（参考値として表示するだけ）。
- 計算: `python3 poc/scripts/two_axis.py W5`（`results/workflow/W5/two_axis.json` と全 W 横断の `summary.md` を作る）。report.md / report.html の「2 本立ての点数」の節は `report_w5.py` が同じ計算から足す。
