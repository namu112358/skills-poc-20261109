# F2 の正解（大きなリファクタリングで消えた振る舞い）

| ID | 種類 | 場所 | 仕組み（核心） | 正しい直し方 |
|---|---|---|---|---|
| B1 | 消えた検証 | `src/lib/tasks/validation.ts` の `validateTaskInput` の `title` | 元はタイトルを 1〜200 文字に限っていた（`b.title.length > 200`）が、分けたときに長さの確認が消え、201 文字以上も通る。エラーの文言は「1〜200 文字」のまま | 長さの確認（`b.title.length > 200`）を戻す |
| B2 | 消えた検証 | `src/lib/tasks/validation.ts` の `validateTaskInput` の `assignee`（引数 `_db` が使われていない） | 元は担当者が `users` に実在するかを DB で確かめていたが、文字列かどうかだけになり、存在しない担当者でも通る（作成は外部キーで 500、更新も同様） | DB で担当者の存在を確かめる処理を戻す |
| T1 | 消えたテスト | `tests/task-validation.test.ts`（元の `tests/tasks.test.ts` の "reports every invalid field"） | すべての項目が誤っているときに 4 つとも報告することを確かめるテストが、分けたときに消えている。B2 のために落ちるはずのテストで、消えたことで B2 に気づけない | テストを戻す（B2 を直せば通る） |

### おとり（不具合ではない変更。指摘したら誤った指摘）

| ID | 場所 | 見た目 | 正しい理由 |
|---|---|---|---|
| D1 | `listTasks`・`getTask`・`createTask`・`updateTask`・`parseTaskId`・型と値の定義 | 大量の行が消えて足されている | 中身は元のまま移しただけ |
| D2 | 呼び出し側の `@/lib/tasks/index` | 読み込み先の変更 | 分けたファイルの入口で、書き出す名前は元と同じ |

- 一致の基準: 場所と仕組みの核心の両方を述べていれば一致。T1 は「元にあったテスト（すべての誤りを報告する）が消えている」ことを述べていれば一致（「テストが足りない」だけの一般論は一致にしない）。
- 直した後の採点は、隠しテスト（消えた 3 つと、元の振る舞い）で行う。
