タスクごとに作業時間を記録できるようにしてください。チームのメンバー（利用者は全員日本国内で働いています）が、タスク詳細画面（/tasks/:id）で、そのタスクに使った時間を記録し、一覧で確認し、記録を取り消せるようにします。工数の振り返りに使う予定です。仕様は次のとおりです。

## データ

- 作業時間の記録は次の項目を持つ: ID（整数）、対象のタスク、記録した人（ユーザー）、作業日、作業時間（分）、メモ、記録日時。
- 作業日は `YYYY-MM-DD` 形式の日付。記録日時は ISO 8601 形式の UTC（例: `2026-11-09T03:04:05.000Z`）で保存する。
- 記録の編集機能は作らない（間違えたら削除して記録し直す）。

## API

すべてログインが必要。未ログインなら 401 を返す。エラーは既存の API と同じ `{ error, details? }` の JSON で返す。
記録は次の JSON で表す。

```json
{ "id": 1, "taskId": 3, "userId": "sato", "userName": "佐藤", "workDate": "2026-11-09", "minutes": 90, "note": "設計レビュー", "createdAt": "2026-11-09T03:04:05.000Z" }
```

| メソッドとパス | 動作 | 成功時 |
|---|---|---|
| `GET /api/tasks/:id/time-entries` | そのタスクの記録を返す。並び順は作業日の新しい順、同じ作業日の中では記録日時の新しい順 | 200 `{ "entries": [ ... ], "totalMinutes": 150 }`（無ければ空配列と 0） |
| `POST /api/tasks/:id/time-entries` | 本文 `{ "workDate": "2026-11-09", "minutes": 90, "note": "..." }` で記録する | 201 `{ "entry": { ... } }` |
| `DELETE /api/tasks/:id/time-entries/:entryId` | 記録を削除する | 204（本文なし） |

- タスクが存在しないときは 404。
- `totalMinutes` はそのタスクの記録の作業時間の合計（全員分）。
- 作業日（`workDate`）は省略できる。省略したときは今日の日付にする。
- 作業時間（`minutes`）は分単位で指定する。無いときは 400（`details` に理由）。
- メモ（`note`）は任意。前後の空白を取り除いてから保存し、省略したときは空文字にする。取り除いた後が 200 文字を超えるときは 400。
- 記録の ID が無い、または URL のタスクの記録でないときの削除は 404。

## 画面（タスク詳細画面 /tasks/:id）

- タスクの情報の下に「作業時間」の見出しを置き、記録を API と同じ順に並べる。各記録は `data-testid="time-entry"` の要素とし、作業日・記録した人の名前（例: 佐藤）・作業時間・メモを表示する。
- 作業時間は「1時間30分」の形で表示する（60 分未満は「45分」、ちょうどの時間は「2時間」）。
- 記録の下に、合計を `data-testid="time-total"` の要素で「合計 2時間30分」の形で表示する（記録が無いときは「合計 0分」）。
- 記録が無いときは「作業時間の記録はまだありません。」と表示する。
- 記録フォーム: `<form aria-label="作業時間">` の中に、作業日の `<input type="date" name="workDate">`（最初は今日の日付が入っている）、作業時間（分）の `<input name="minutes">`、メモの `<input name="note">` と「記録する」ボタン。記録するとページを再読み込みしなくても（再読み込みしてもよい）、記録が一覧と合計に反映される。
- 画面からの記録・削除は、上の API を呼び出して行う。
- 記録できなかったとき（API がエラーを返したとき）は、フォームの近くに `role="alert"` でエラーを表示する。
- 自分が記録したものにだけ「削除」ボタンを表示する。押すとその記録が一覧から消え、合計にも反映される。
