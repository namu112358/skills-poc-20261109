# PR: 計測器ごとの定期点検（担当者・周期・点検記録）を追加

## 依頼

計測器ごとに、定期点検の担当者と点検の記録を持てるようにしてほしい。

## 合意した要件（依頼者との確認で決まったこと）

- 点検の担当者は、在籍している利用者から 1 台につき 1 人選ぶ。退職・休職中の人は新しく選べない。すでに担当になっている計測器は、そのまま表示してよい。
- 点検の記録は、点検日・点検した人（在籍している利用者）・結果（良好か要修理）・メモ。1 台につき何回分も残す。点検した人は担当者以外でもよい。
- 点検の記録は消さない。間違えたら訂正の記録を足す。
- 点検の周期は計測器ごと（月単位。既定 3 か月）。次の点検予定日は「最後の点検日 + 周期」。記録が 1 回も無い計測器は「未点検」として目立たせる。
- 担当者で絞り込み・並べ替えができる。担当者ごとに、点検が遅れている台数を毎朝知りたい。
- 「要修理」になったら、その計測器を使用停止にする。
- 今の台帳の「その他の項目」の点検者・最終点検日を引き継ぐ。利用者と分かる名前（敬称つきも）はその人を担当者に、分からないものと読めない日付は元の書き方を残す。黙って捨てない。
- 本番の計測器は約 5 万件。点検の一覧は毎朝開くので遅いと困る。
- 「その他の項目」の担当部署（dept）は別のシステムが DB を直接読むので、持ち方を変えない。
- 不具合が出たら前の版のアプリに戻すことがある（DB はそのまま使う）。

## 変更内容

- マイグレーション 6: 担当者・点検周期（既定 3 か月）・点検記録テーブル
- 旧 extra の inspector / last_inspected を移行（名前が分かれば担当者に、分からない・読めないものは元の書き方を残す）
- 要修理の点検記録で計測器を使用停止にする
- API: /api/instruments/:id/inspection, /inspections。詳細・一覧画面に表示
