タスクにタグを付けられるようにしてください。ログイン中のユーザーが、タスク詳細画面（/tasks/:id）でタグを付け外しでき、タスク一覧（/tasks）でタグを見て、タグで絞り込めるようにします。仕様は次のとおりです。

## データ

- タグは名前だけを持つ。1 つのタスクに複数のタグを付けられ、同じタグを複数のタスクに付けられる。同じタスクに同じ名前のタグは 1 回だけ付く。
- タグの名前は、前後の空白を取り除いてから扱う。取り除いた後が 1〜20 文字で、空白・カンマ（`,`）・スラッシュ（`/`）を含まないこと。英字の大文字と小文字は区別する（`Bug` と `bug` は別のタグ）。
- タスクに付いているタグは、付けた古い順に並べる。
- タグを付け外しできるのは、ログイン中のユーザー全員（タスクの担当者に限らない）。

## API

すべてログインが必要。未ログインなら 401 を返す。エラーは既存の API と同じ `{ error, details? }` の JSON で返す。

| メソッドとパス | 動作 | 成功時 |
|---|---|---|
| `GET /api/tasks/:id/tags` | そのタスクのタグを、付けた古い順に返す | 200 `{ "tags": ["急ぎ", "バグ"] }`（無ければ空配列） |
| `POST /api/tasks/:id/tags` | 本文 `{ "name": "急ぎ" }` のタグを付ける | 201 `{ "tags": [ ... ] }`（付けた後のそのタスクのタグ） |
| `DELETE /api/tasks/:id/tags/:name` | タグを外す（`:name` は URL エンコードしたタグの名前） | 204（本文なし） |
| `GET /api/tasks?tag=急ぎ` | 既存の一覧 API に、タグでの絞り込みを追加する | 200 `{ "tasks": [ ... ] }`（そのタグが付いたタスクだけ） |

- タスクが存在しない（ID が正の整数でない場合も含む）ときは 404。
- 名前が上の条件を満たさないときは 400（`details` に理由）。本文が無い・`name` が文字列でない・JSON として読めないときも 400。
- すでに付いているタグを付けようとしたら 409。外そうとしたタグがそのタスクに付いていなければ 404。
- `GET /api/tasks` の `tag` は `status` と同時に指定でき、両方を満たすタスクだけを返す。`tag` が空のときは指定なしとして扱う。どのタスクにも付いていないタグを指定したら空配列を返す。

## 画面

### タスク詳細画面（/tasks/:id）

- タスクの情報の下に「タグ」の見出しを置き、タグを付けた古い順に並べる。各タグは `data-testid="tag"` の要素とし、タグの名前を表示する。
- タグが無いときは「タグはまだありません。」と表示する。
- 各タグに「外す」ボタン（`aria-label="タグ「急ぎ」を外す"` のように、外すタグの名前を含める）を置く。押すとそのタグが一覧から消える。
- タグの追加フォーム: `<form aria-label="タグの追加">` の中に `<input name="name">` と「追加する」ボタン。追加すると、ページを再読み込みしなくても（再読み込みしてもよい）一覧に表示され、入力欄は空に戻る。
- 追加できなかったとき（空白だけの名前、すでに付いているタグなど）は、フォームの近くに `role="alert"` でエラーを表示する。
- タグの名前はテキストとして表示する（HTML として解釈しない）。

### タスク一覧（/tasks）

- 各タスクの行に、そのタスクのタグを付けた古い順に表示する。各タグは、そのタグで絞り込んだ一覧（`/tasks?tag=<URL エンコードしたタグの名前>`）へのリンクにする。
- `/tasks?tag=急ぎ` のようにタグを指定すると、そのタグが付いたタスクだけを表示する。既存のステータスの絞り込みと同時に使える（`/tasks?tag=急ぎ&status=todo`）。
- タグで絞り込んでいる間は、一覧の上に「タグ「急ぎ」のタスク」と表示し、絞り込みを解除して全件に戻る「すべてのタスク」というリンクを置く。
