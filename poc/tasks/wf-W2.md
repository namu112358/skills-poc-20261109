タスクにコメントを付けられるようにしてください。ログイン中のユーザーが、タスク詳細画面（/tasks/:id）でコメントを読み書き・削除できるようにします。仕様は次のとおりです。

## データ

- コメントは次の項目を持つ: ID（整数）、対象のタスク、投稿者（ユーザー）、本文、投稿日時。
- 投稿日時は ISO 8601 形式の UTC（例: `2026-11-09T03:04:05.000Z`）で保存する。
- コメントの編集機能は作らない。

## API

すべてログインが必要。未ログインなら 401 を返す。エラーは既存の API と同じ `{ error, details? }` の JSON で返す。
コメントは次の JSON で表す。

```json
{ "id": 1, "taskId": 3, "author": "sato", "authorName": "佐藤", "body": "本文", "createdAt": "2026-11-09T03:04:05.000Z" }
```

| メソッドとパス | 動作 | 成功時 |
|---|---|---|
| `GET /api/tasks/:id/comments` | そのタスクのコメントを投稿の古い順に返す | 200 `{ "comments": [ ... ] }`（無ければ空配列） |
| `POST /api/tasks/:id/comments` | 本文 `{ "body": "..." }` でコメントを投稿する | 201 `{ "comment": { ... } }` |
| `DELETE /api/tasks/:id/comments/:commentId` | コメントを削除する | 204（本文なし） |

- タスクが存在しない（ID が正の整数でない場合も含む）ときは 404。
- 投稿者は常にログイン中のユーザーにする。リクエスト本文に投稿者が含まれていても使わない。
- 本文は前後の空白を取り除いてから保存する。取り除いた後が 1〜1000 文字でなければ 400（`details` に理由）。本文が無い・文字列でない・JSON として読めないときも 400。
- 削除できるのはコメントの投稿者本人だけ。他人のコメントを削除しようとしたら 403。コメントが無い、または URL のタスクのコメントでないときは 404。

## 画面（タスク詳細画面 /tasks/:id）

- タスクの情報の下に「コメント」の見出しを置き、コメントを投稿の古い順に並べる。各コメントは `data-testid="comment"` の要素とし、投稿者の名前（例: 佐藤）・本文・投稿日時を表示する。
- コメントが無いときは「コメントはまだありません。」と表示する。
- 本文はテキストとして表示する（HTML として解釈しない）。改行はそのまま表示されるとよい。
- 投稿フォーム: `<form aria-label="コメント">` の中に `<textarea name="body">` と「投稿する」ボタン。投稿するとページを再読み込みしなくても（再読み込みしてもよい）、投稿したコメントが一覧に表示される。
- 投稿できなかったとき（空白だけの本文など）は、フォームの近くに `role="alert"` でエラーを表示する。
- 自分が投稿したコメントにだけ「削除」ボタンを表示する。押すとそのコメントが一覧から消える。
