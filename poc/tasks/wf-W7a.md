タスクの「完了報告」をできるようにしてください。担当者がタスクを完了にするときに、誰がいつ完了したかとメモを残せるようにします。仕様は次のとおりです。

## データ

- 完了報告は次の項目を持つ: 対象のタスク、完了した人（ユーザー）、完了日時、メモ。
- 1 つのタスクに完了報告は 1 件まで。

## API

すべてログインが必要。未ログインなら 401 を返す。
完了報告は次の JSON で表す（`completedAt` は完了日時）。

```json
{ "taskId": 3, "completedBy": "sato", "completedByName": "佐藤", "completedAt": "…", "note": "メモ" }
```

| メソッドとパス | 動作 | 成功時 |
|---|---|---|
| `GET /api/tasks/:id/completion` | そのタスクの完了報告を返す | 200 `{ "completion": { ... } }`（無ければ `{ "completion": null }`） |
| `POST /api/tasks/:id/completion` | 本文 `{ "note": "..." }` で完了報告をし、タスクのステータスを完了（`done`）にする | 201 `{ "completion": { ... } }` |
| `DELETE /api/tasks/:id/completion` | 完了報告を取り消し、タスクのステータスを進行中（`in_progress`）に戻す | 204（本文なし） |

- タスクが存在しない（ID が正の整数でない場合も含む）ときは 404。
- 完了報告できるのは、そのタスクの担当者だけ。担当者以外が完了報告しようとしたら 403。すでに完了（`done`）のタスクに完了報告しようとしたら 409。
- 完了した人は常にログイン中のユーザーにする。リクエスト本文に含まれていても使わない。
- メモは省略できる（省略したときは空文字）。前後の空白を取り除いてから保存する。文字列でない、または取り除いた後が 500 文字を超えるときは 400。リクエスト本文が JSON のオブジェクトでない（JSON として読めない場合も含む）ときも 400（`{}` は可）。
- 取り消しできるのは、完了報告をした本人だけ。ほかの人が取り消そうとしたら 403。完了報告が無いタスクを取り消そうとしたら 409。
- 既存の `PATCH /api/tasks/:id` の動作は変えない。

## 画面（タスク詳細画面 /tasks/:id）

- 完了報告があるときは、タスクの情報の下（コメントの上）に「完了報告」の見出しと `data-testid="completion"` の要素を置き、完了した人の名前（例: 佐藤）・完了日時・メモを表示する。
- 完了報告が無いときは、この見出しと要素を表示しない。
- 画面から完了報告・取り消しをする操作（フォームやボタン）は、今回は作らない。
