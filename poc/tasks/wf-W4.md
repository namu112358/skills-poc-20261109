タスクをチームで共有できるようにしてください。今はログインしたユーザー全員がすべてのタスクを見て編集できますが、これを「自分の個人タスク」と「自分が所属するチームのタスク」だけに限ります。仕様は次のとおりです。

## チームと役割

- チームは ID（整数）と名前を持つ。ユーザーは複数のチームに所属できる。
- チーム内の役割は「管理者」（`admin`）と「メンバー」（`member`）の 2 つ。
- 初期データ（空の DB から始めたとき）:
  - チーム 1「開発チーム」: sato（管理者）、suzuki（メンバー）
  - チーム 2「デザインチーム」: suzuki（管理者）、tanaka（メンバー）

## タスクの所属と権限

- タスクは「個人タスク」か「チームのタスク」のどちらか。タスクには作成者を記録する。
- 個人タスク: 作成者だけが閲覧・編集できる。担当者は作成者本人だけにできる。
- チームのタスク: そのチームのメンバー全員（役割を問わない）が閲覧・編集できる。担当者はそのチームのメンバーから選ぶ。
- 閲覧できないタスクは、存在しないタスクと同じに扱う（API は 404、画面は 404 ページ）。
- チームから外されたユーザーは、そのチームのタスクを閲覧・編集できなくなる（担当者のままになっているタスクも含む）。
- 初期データのタスクの所属:

  | タスク | 所属 | 作成者 |
  |---|---|---|
  | 1〜3、5 | 開発チーム | sato |
  | 4 | デザインチーム | suzuki |
  | 6 | sato の個人タスク | sato |
  | 7 | tanaka の個人タスク | tanaka |

- この変更より前から DB にあるタスクは、担当者の個人タスク（作成者 = 担当者）にする。既存の DB に初期データのチームを追加する必要はない。

## API

すべてログインが必要（未ログインは 401）。エラーは既存の API と同じ `{ error, details? }` の JSON で返す。入力誤りは 400、権限が無い操作は 403、対象が無い（閲覧できない場合を含む）ときは 404。

### タスク（既存の API の変更）

タスクの JSON に、所属チームの ID `teamId`（個人タスクは `null`）と作成者のユーザー ID `owner` を加える。

```json
{ "id": 1, "title": "要件定義書のレビュー", "status": "done", "assignee": "sato", "dueDate": "2026-11-02", "teamId": 1, "owner": "sato" }
```

- `GET /api/tasks`: 閲覧できるタスクだけを返す。`?teamId=<チームの ID>` でそのチームのタスクだけ、`?teamId=personal` で自分の個人タスクだけに絞り込む。不正な値は「指定なし」として扱う。既存の `status` と併用できる。
- `POST /api/tasks`: 本文の `teamId` を受け付ける（省略または `null` で個人タスク）。存在しないチーム・自分が所属していないチームを指定したら 400。作成者は常にログイン中のユーザーにする（本文に `owner` があっても使わない）。担当者が上の規則に合わないときは 400。
- `GET /api/tasks/:id`: 閲覧できないタスクは 404。
- `PATCH /api/tasks/:id`:
  - 閲覧できないタスクは 404。
  - 担当者を変えるときは、上の規則で検証する（合わなければ 400）。
  - `teamId` を送ると所属を変えられる（別のチームへの付け替え、`null` で個人タスクにする）。所属を変えられるのはタスクの作成者だけで、作成者以外は 403。変更先は自分が所属するチームか `null` だけ（それ以外は 400）。変更後の担当者が規則に合わないときも 400。
  - `owner` は変更できない（送られても使わない）。

### チーム（新しい API）

| メソッドとパス | 動作 | 成功時 |
|---|---|---|
| `GET /api/teams` | 自分が所属するチームを ID 順に返す | 200 `{ "teams": [{ "id": 1, "name": "開発チーム", "role": "admin" }] }` |
| `POST /api/teams` | 本文 `{ "name": "..." }` でチームを作る。作った人が管理者になる | 201 `{ "team": { "id": 3, "name": "...", "role": "admin" } }` |
| `GET /api/teams/:id/members` | メンバーをユーザー ID 順に返す | 200 `{ "members": [{ "userId": "sato", "name": "佐藤", "role": "admin" }] }` |
| `POST /api/teams/:id/members` | 本文 `{ "userId": "...", "role": "member" }` でメンバーを追加する（`role` を省略したら `member`） | 201 `{ "member": { "userId": "...", "name": "...", "role": "..." } }` |
| `DELETE /api/teams/:id/members/:userId` | メンバーをチームから外す | 204（本文なし） |

- チーム名は前後の空白を取り除いてから保存する。取り除いた後が 1〜50 文字でなければ 400。
- 自分が所属していないチーム・存在しないチーム（ID が正の整数でない場合も含む）は、どの API でも 404。
- メンバーの追加・削除ができるのは、そのチームの管理者だけ。管理者でないメンバーが行うと 403。
- 追加: 存在しないユーザー・不正な `role` は 400。既に所属しているユーザーは 409。
- 削除: 対象のユーザーがそのチームに所属していなければ 404。チームの最後の管理者は外せない（400）。管理者が自分自身を外すことは、ほかに管理者がいればできる。

## 画面

- ヘッダーに「チーム」のリンク（`/teams`）を加える。
- タスク一覧（`/tasks`）: 閲覧できるタスクだけを表示する。各行に所属（チーム名、個人タスクは「個人」）を `data-testid="task-team"` の要素で表示する。絞り込みフォームに `<select name="teamId">` を加える（選択肢は「すべて」（値は空）、「個人」（値は `personal`）、所属する各チーム（値はチームの ID））。
- タスク詳細（`/tasks/:id`）: 閲覧できないタスクは 404 ページ。所属（チーム名か「個人」）を `data-testid="task-team"` の要素で表示する。
- チーム一覧（`/teams`）: 所属するチームを `data-testid="team"` の要素で並べ、チーム名、自分の役割（「管理者」か「メンバー」）、チーム詳細へのリンクを表示する。チームを作る画面は無くてよい。
- チーム詳細（`/teams/:id`）: メンバーを `data-testid="member"` の要素で並べ、名前と役割（「管理者」か「メンバー」）を表示する。所属していないチームは 404 ページ。
  - 管理者にだけ、メンバーを追加するフォーム（`<form aria-label="メンバーの追加">` の中に `name="userId"` の入力欄（`input` か `select`）と「追加する」ボタン。追加される役割はメンバー）と、各メンバーの「外す」ボタンを表示する。
  - 追加・削除の結果は、ページを再読み込みしなくても（再読み込みしてもよい）一覧に反映する。失敗したときはフォームの近くに `role="alert"` でエラーを表示する。
