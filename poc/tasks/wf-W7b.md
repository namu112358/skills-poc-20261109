タスクに作業記録（作業した時間）を残せるようにしてください。ログイン中のユーザーが API で作業時間を記録・削除でき、タスク詳細画面（/tasks/:id）で記録と合計を見られるようにします。仕様は次のとおりです。

## データ

- 作業記録は次の項目を持つ: ID（整数）、対象のタスク、記録した人（ユーザー）、作業時間（分）、メモ、記録日時。
- 作業記録の編集機能は作らない。

## API

すべてログインが必要。未ログインなら 401 を返す。
作業記録は次の JSON で表す（`recordedAt` は記録日時）。

```json
{ "id": 1, "taskId": 3, "author": "sato", "authorName": "佐藤", "minutes": 30, "note": "メモ", "recordedAt": "…" }
```

| メソッドとパス | 動作 | 成功時 |
|---|---|---|
| `GET /api/tasks/:id/worklogs` | そのタスクの作業記録を新しい順（記録日時の新しい順。同じなら ID の大きい順）に返し、作業時間の合計も返す | 200 `{ "worklogs": [ ... ], "totalMinutes": 90 }`（無ければ空配列と 0） |
| `POST /api/tasks/:id/worklogs` | 本文 `{ "minutes": 30, "note": "..." }` で作業記録を追加する | 201 `{ "worklog": { ... } }` |
| `DELETE /api/tasks/:id/worklogs/:worklogId` | 作業記録を削除する | 204（本文なし） |

- タスクが存在しない（ID が正の整数でない場合も含む）ときは 404。
- 作業時間（`minutes`）は 1〜1440 の整数。それ以外（小数・文字列・省略を含む）は 400。
- メモは省略できる（省略したときは空文字）。前後の空白を取り除いてから保存する。文字列でない、または取り除いた後が 200 文字を超えるときは 400。リクエスト本文が JSON のオブジェクトでない（JSON として読めない場合も含む）ときも 400。
- 完了（`done`）のタスクには作業記録を追加できない。追加しようとしたら 409。
- 記録した人は常にログイン中のユーザーにする。リクエスト本文に含まれていても使わない。
- 削除できるのは、記録した本人だけ。ほかの人が削除しようとしたら 403。作業記録が無い、または URL のタスクの記録でないときは 404。

## 画面（タスク詳細画面 /tasks/:id）

- タスクの情報の下（コメントの上）に「作業記録」の見出しを置き、作業記録を新しい順に並べる。各記録は `data-testid="worklog"` の要素とし、記録した人の名前（例: 佐藤）・作業時間（例: 30 分）・メモ・記録日時を表示する。
- 合計を `data-testid="worklog-total"` の要素に「合計 90 分」の形で表示する。
- 作業記録が無いときは「作業記録はまだありません。」と表示する（合計は「合計 0 分」でも、表示しなくてもよい）。
- 画面から記録・削除をする操作（フォームやボタン）は、今回は作らない。
