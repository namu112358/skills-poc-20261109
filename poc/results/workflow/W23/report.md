# W23 要件の書かれていない PR・大きな PR でのレビューの比較 — 結果レポート

- 実施: 2026-11-11。設計: [`poc/tasks/wf-W23-design.md`](../../../tasks/wf-W23-design.md)。判断の記録: [`decisions.md`](decisions.md)。集計表の全体: [`tables.md`](tables.md)。
- 題材: PR の説明が 1〜2 行だけの作り物 3 つ。d1 ダッシュボード（不具合 5）、d2 コメント（不具合 4）、d3 は d1 と d2 を 1 つにまとめた約 430 行の PR（不具合 9）。
- 設定: Sonnet の道具なし・Haiku の道具なし・内蔵 `/code-review high`・`/review-pr`・`ce-code-review`（どれも既定の動き）。3 題材 × 5 設定 × 2 回 = 30 本。全試行が REVIEW.md をコミットして終わり、介入は 0 回。
- 判定: W21 と同じ判定役（Opus）・同じ基準。10 件を 2 回判定し、一致率は 1.0。

## 結論

- **9 つの不具合のうち 8 つは、全設定がほぼ毎回見つけた。** 要件の書かれていない PR でも、利用者をまたぐキャッシュ・XSS（リンクの URL）・編集の認可の抜け・共有の定数の書き換え・日時を文字列で並べる誤りなどは、道具の有無に関係なく見つかった（大きな PR の d3 で、Haiku が B8 を 1 回落としただけ）。
- **差が出たのは、日曜に翌週を指す不具合（B2）だけ。** 曜日の数え方の境界で、コードを読んだだけでは気づきにくい。
  - 見つけた回数（d1 と d3 の計 4 回中）: Haiku の道具なし 3、CE 2、内蔵 `/code-review high` 1、`/review-pr` 1、Sonnet の道具なし 0。
  - **実際にコードを動かしたかどうかと強く結びついていた。** Haiku の道具なしは 4 本すべてで `node` を使って関数を動かし（1 本あたり 2〜5 回）、3 本で B2 を見つけた。Sonnet の設定は 20 本中 2 本しか動かさず（1 回ずつ）、B2 を見つけた試行も読んで気づいたもの。
- **大きな PR では、気づきにくい不具合の見落としが増えた。** B2 は、小さな PR（d1）では 10 回中 6 回見つかったが、まとめた PR（d3）では 10 回中 3 回だった。ほかの不具合では差が無かった。
- **道具の有無・種類による差は小さく、費用の差は大きい。** 見つけた不具合の計（36 中）は 32〜34 で、どの設定も同じくらい。費用は Haiku の道具なしが 1 本 $0.03、Sonnet の道具なしが $0.22、CE が $0.60。
- 開発フローへの意味（暫定）: レビューの道具より、「疑わしい所を実際に動かして確かめる」ことの方が、見落としを減らすのに効きそう。これは W24 で、動かすよう指示したときに差が出るかを確かめる。大きな PR は、気づきにくい不具合を見落としやすくなるので、PR を小さく分ける意味がある。
