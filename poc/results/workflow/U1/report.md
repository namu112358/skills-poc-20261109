# 開発ワークフロー PoC — U1 UI/UX 系ツールの組み合わせの比較

実施日 2026-11-11 ・ モデル claude-sonnet-5-5 ・ Claude Code 2.1.322 ・ 設計 [poc/tasks/wf-U1-design.md](../../../tasks/wf-U1-design.md)

> **2026-11-12 追記（確定）: 見た目の評価は、依頼者の二択の評価（85 回）で確定した。** 勝率は Impeccable 79%・4 つすべて 66%・Frontend Design 40%・ツールなし 32%・UI/UX Pro Max 16%（[human-pairs.md](human-pairs.md)）。下の「暫定」の見た目の結論は、AI の判定によるもので置き換える。特に「業務の画面では Frontend Design が安く評価も高い」は、人の評価では支持されなかった（一覧画面 Frontend Design 43%・Impeccable 57%、ダッシュボード 25%・86%）。AI の判定と人の選択の一致は 61%。この結果、標準は Impeccable と Web Design Guidelines の 2 つにした（[ui-ux-overlap.md](../../../../docs/tool-candidates/ui-ux-overlap.md)）。

> **暫定の報告です。** 見た目の主な評価は、依頼者による順位付け（構成の名前を伏せた画面を並べ替える）です。依頼者の順位付けはまだ付いていないため、この報告の見た目の評価は、補助の AI の判定（`claude-opus-5-5`）によるものです。順位付けが付いたら、主な評価をそれに差し替えます。

## 結論（暫定）

- **ツールは「入れる」だけでなく「呼ばれる」ことが効く。** 依頼文を渡すだけ（Skill の自動発火）では、デザインの Skill が呼ばれないことがよくあった。呼ばれた試行は、呼ばれなかった試行より AI の見た目の判定が高い傾向（20 点中 0〜1.7 点）。
- **4 つすべてを入れた今の標準は、どれか 1 つに絞った構成を上回らない。** 作る課題 20 本のうち、デザインの Skill が呼ばれたのは 11 本で、呼ばれたのはほぼ Frontend Design か Impeccable。UI/UX Pro Max と Web Design Guidelines は、作る課題では一度も選ばれなかった。
- **作る担当は、題材で向き不向きがある。**
  - 宣伝のページ（紹介ページ・SaaS の LP）では Impeccable の評価が高い。ただし、費用と時間はほかの約 2〜3 倍かかる。
  - 業務の画面（一覧・ダッシュボード）では、Frontend Design が安く、評価も高い。
  - 登録フォームでは差が小さい。Frontend Design はツールなしより低かった。
- **UI/UX Pro Max は、入れた効果が見えない。** 単体で入れても半分以上の試行で呼ばれず、評価はツールなしと同程度。
- **UI のレビュー（U1c）では、ツールの差が出なかった。** どの構成も、仕込んだ 9 件の問題をすべて見つけた。課題が簡単すぎ、モデルだけで足りた。
- **機械の検査（機能・アクセシビリティ・スマートフォンの幅）では差がない。** ほぼ全試行が 50 点中 46〜50 点。

整理案 A（Impeccable + Web Design Guidelines、UI/UX Pro Max は既定で無効）は、方向としては支持される。ただし、Impeccable の費用の高さと、業務の画面では Frontend Design の方が良い点を踏まえ、標準の決め方は U2（使う Skill を `CLAUDE.md` で指定したときの効果）の結果と、依頼者の順位付けを見てから決める。

## 課題と構成

| 課題 | 内容 |
|---|---|
| U1a | 未ログインの人向けの紹介ページ（新規） |
| U1b | タスク一覧画面の見た目と使い勝手の改善（業務の画面） |
| U1c | 「マイタスク」画面の差分の UI レビュー（問題 9 件・おとり 5 件を仕込んだもの） |
| U1d | 社外向けの SaaS の LP（料金・よくある質問を含む） |
| U1e | リーダーが毎朝見るダッシュボード |
| U1f | タスクの新規登録フォーム |

| 構成 | 中身 |
|---|---|
| ツールなし | デザイン系のツールなし |
| 4 つすべて | Frontend Design・Web Design Guidelines・Impeccable・UI/UX Pro Max（W1〜W20 の条件） |
| Impeccable（整理案 A） | Impeccable + Web Design Guidelines |
| Frontend Design | Frontend Design + Web Design Guidelines |
| UI/UX Pro Max | UI/UX Pro Max + Web Design Guidelines |

試行は、作る課題が 5 題材 × 5 構成 × 4 回 = 100 本、レビューが 5 構成 × 2 回 = 10 本。試行の費用の合計は約 $79、判定役の費用は約 $9。

## 判断の記録

- **許可リスト**: Web Design Guidelines がルールを取得できるよう、子セッションの許可リストに `WebFetch(domain:raw.githubusercontent.com)` を全構成に同じく足した（CLAUDE.md の例外。コーディネーターの判断）。
- **評価方法の変更**（試行の前）: 依頼者と相談し、見た目の主な評価を、AI の判定から人の順位付けに変えた。作る課題の回数を 2 回から 4 回に増やした。
- **題材の追加**（試行の途中）: 依頼者の指示で、U1d〜f を足した。U1a〜c の課題と採点は変えていない。
- **順位付けのページ**: 依頼者の指示で、パソコンの幅（1280px）の画面だけを見せる形にした。スマートフォンの幅は、機械の検査（横スクロールの有無・axe）だけで見ている。
- **採点の誤りの修正**: ログイン画面へのリンクの検査で、Next.js の画面内の移動を待たずに判定していた。誤って落とした 2 試行（U1a の Frontend Design #3・ツールなし #3）は、保存した差分から作り直して採点し直した（`poc/scripts/regrade_u1.py`）。SaaS の LP の同じ検査は、本番の前に直した。
- **まとめ役のスクリプトの停止**: 試行の途中で `run_u1_trials.sh` を書き換えたため、最初のまとめ役の処理がエラーで終わった。その時点で全試行が済んでいて、結果は失われていない。以後、実行中のスクリプトは置き換えの形でだけ変えた。
- **Web Design Guidelines の切り分け**: ツールなし以外のすべての構成に入れているため、単体の効果は分からない（依頼者と相談して決めた）。

## 限界

- 見た目の評価は、今は AI の判定だけ。依頼者の順位付けで確定させる。
- 各構成 4 回で、1 点前後の差は区別できない。
- 子セッションのモデルは Sonnet。より強いモデルではツールの差が小さくなる可能性がある。
- UI レビューの課題は簡単すぎて、全構成が満点近くに張り付いた。

## 次に確かめること

- **U2**（実行中）: 使う Skill を `CLAUDE.md` で指定すれば、確実に呼ばれ、評価が上がるか。4 つすべてのままでも、役割を割り振れば使えるか。
- 見つけにくい問題を仕込んだ UI レビューで、ツールの差が出るか。
