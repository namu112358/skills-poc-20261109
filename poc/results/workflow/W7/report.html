実施日 2026-11-09 ・ モデル claude-sonnet-5-5 ・ Claude Code 2.1.319 ・ 計画書 poc/PLAN.md §5.1

W7（続けて行う作業での学習効果）では、品質に差は出ませんでした。4 候補と baseline の各 2 組（全 10 組）が、W7b（作業記録）で 2 件の落とし穴（日時は UTC で保存し JST で表示する、新しい API は独自のエラー型で返す）をレビューの指摘の前に避け、受け入れテストも 14/14 でした（品質は全組 100 点）。

W7a（完了報告）で落とし穴を外したのは Feature Dev #1・Compound Engineering #1・#2 の 3 組（いずれも P2 のエラー型）で、3 組とも W7b では指摘の前に避けました（同じ間違いの繰り返しは 0 件）。Compound Engineering は /ce-compound で決まりを docs/solutions/ に残し、#2 は W7b の最初の調査でそれを読みました。

ただし、前の段階の知見が無い対照（W7a を引き継がず、W7a の参照実装だけがある状態で W7b を実行）でも 4 候補すべてが 2 件とも避けたため、W7b での回避は「W7a で直ったコードが手本として残っていること」で説明でき、記憶の仕組みの効き目はこの 2 段階の設計では切り分けられません。

効率（同じ品質での費用・時間。基準は baseline 2 組の W7b の平均 $0.39・109 秒）は baseline（100 点）と Superpowers（97 点）が最も良く、Feature Dev 80 点、gstack 39 点、Compound Engineering 36.5 点です。続けて行った W7b の費用は対照と比べても下がっておらず（Compound Engineering $5.67 対 $3.96、gstack $3.48 対 $3.02）、記憶を引き継ぐことによる費用・時間の削減は見られませんでした。

計算方法と判断の記録

  • 品質 = （W7b で落とし穴を避けた数 50 + W7b の受け入れ 20）の得点 ÷ 70 × 100。
  • 効率 = 費用 50 + 時間 30 + 介入 20。費用・時間は baseline（$0.3935・108.5 秒）に対する倍率で、2 倍以下 = 満点、3 倍以下 = 80%、5 倍以下 = 60%、10 倍以下 = 30%、10 倍超 = 0。介入は 0 回 = 20、1 回 = 10、2 回以上 = 0。
  • 質問の回数は効率から引かない（参考値）。品質の差が、比べる 2 候補の 2 回の差（ばらつき）の大きい方以下なら「差なし」とする。

所見

  • 品質（W7b の落とし穴 + 受け入れ）は 10 組すべて 100 点で、候補の間に差はありません。W7a の受け入れテストも全組 16/16 でした。
  • W7a で落とし穴を外したのは 3 組で、すべて P2（新しい API で AppError・withApi を使わず、既存のタスク API と同じ jsonError で返した）。P1（日時）は全組が W7a から避けました。既存コードに toUtcIso・formatJst とテストがあり、日時は気づきやすかったと考えられます。
  • W7a で指摘を受けた 3 組（Feature Dev #1、Compound Engineering #1・#2）は、W7b で 3 組とも指摘の前に避けました（同じ間違いの繰り返し 0 件）。ほかの 7 組は W7a でも避けていたため、学ぶ機会自体がありませんでした。
  • 前の段階の知見を読んだ形跡: Compound Engineering #2 は W7b の 1 ステップ目で docs/solutions/conventions/new-api-routes-use-withapi-and-apperror.md を直接読みました。#1 は記録上、W7a の計画書（docs/plans/）を読んだ形跡だけが残り、docs/solutions/ を読んだかはサブエージェントの中で読んだ可能性も含めて確認できませんでした。Feature Dev #1 は記憶の仕組みを持たず、W7a で直したコード（同じ作業用コピーに残る）を手本にしたと考えられます。
  • 対照（W7a を引き継がない W7b、各候補と baseline 1 回）: 5 本とも、指摘の前に 2 件とも避け、受け入れ 14/14 でした。対照の作業用コピーには W7a の参照実装（決まりに沿ったコード）があるので、続けて行った W7b と同じく「手本」はあり、違いは候補の記憶と候補自身の W7a のコードの有無だけです。この差で回避の結果は変わりませんでした。
  • 費用・時間の対照との比較（続けて行った W7b の 2 組平均 / 対照）: baseline $0.39・1.8 分 / $0.42・2.2 分、Superpowers $0.66・3.9 分 / $0.75・3.4 分、Feature Dev $1.30・3.0 分 / $1.36・4.3 分、Compound Engineering $5.67・11.9 分 / $3.96・10.3 分、gstack $3.48・7.5 分 / $3.02・7.2 分。続けて行うことで安く速くなったとは言えず、Compound Engineering は記憶を引き継いだ側の方が高くつきました（#2 は上限 $7.67 で止めた）。
  • W7a → W7b の費用の変化は、baseline $0.44 → $0.39（2 組の平均）、Superpowers $0.63 → $0.66（平均）、Feature Dev $1.42 → $1.30、Compound Engineering $4.97 → $5.67、gstack $2.43 → $3.48。W7b は W7a と別の機能なので、この変化は学習だけでなく課題の違いも含みます。
  • gstack #2 の W7b は、/review が足したテストを未コミットのまま確認待ちで止まり、「お任せします」の介入を 1 回受けました（効率の介入 0 点）。Compound Engineering #2 の W7b は watch の見積もりが上限（$7.67）に達し、/ce-work の途中で止めました（実装とコミットは済んでおり、品質は 100 点）。
