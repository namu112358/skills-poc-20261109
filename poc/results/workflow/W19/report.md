# W19 粗悪な既存実装に引っ張られない — 結果レポート

- **粗悪な既存実装に引っ張られた試行は無かった。** 12 本すべてが、マイグレーションで担当者の列と点検の記録の表を足し、5 万件の旧データを移した（データの持ち方 25 点・移行 20 点をほぼ全員が満点）。この観点では天井に張り付き、候補の差は出なかった。
- 品質の平均: Compound Engineering 97.3 > Feature Dev（代理人なし）92.3 > baseline 91.0 > gstack 88.4 > Feature Dev（代理人あり）88.0 > Superpowers 87.7。差が出たのは、業務の隠れ要件（担当者での絞り込み・担当者ごとの遅れの台数）と設計の筋。
- **人間の代理人は、この W では効き目が見えなかった。** Feature Dev は代理人あり（88.0）がなし（92.3）より低く、差は 2 回の幅（4 点ほど）と同じくらい。代理人に技術的な判断を求めたのは Compound Engineering（12〜13 件）・gstack・Superpowers が多く、baseline と Feature Dev は 0〜1 件だった。
- Compound Engineering は品質が最も高いが、費用は $7.5〜14.2（baseline の 7〜13 倍）。Superpowers は最も安い（$0.8〜1.9）が、1 回目は本番で詳細の画面が 500 になる不具合を残した。

- 効率 = 費用 50 + 時間 30 + 介入 20。費用・時間は baseline（$1.1539・438 秒）に対する倍率で、2 倍以下 = 満点、3 倍以下 = 80%、5 倍以下 = 60%、10 倍以下 = 30%、10 倍超 = 0。介入は 0 回 = 20、1 回 = 10、2 回以上 = 0。
- 質問の回数は効率から引かない（参考値）。品質の差が、比べる 2 候補の 2 回の差（ばらつき）の大きい方以下なら「差なし」とする。
- 定義は poc/PLAN.md §4.4。計算は poc/scripts/two_axis.py。従来の総合点・順位はこの節では変えない。
