# 要件: チーム進捗ダッシュボード

## 背景と目的

- 毎週の定例で、各メンバーに口頭で状況を聞いて回っている。
- 現在のタスク一覧（`/tasks`）は全件が並ぶだけで、「誰がどれくらい抱えているか」「どれが遅れているか」がひと目で分からない。
- 目的: 定例でこの画面を開けば、口頭で聞かなくても進捗が分かる状態にする。

## 目標

1. **期限超過タスクの強調表示（最優先・最も目立たせる）**
   - 「期限を過ぎていて、完了していないタスク」の**件数**を大きく表示する。
   - その**一覧**を表示する。各行に次を出す: タスク名、担当者（名前）、期限、何日過ぎたか。
2. **担当者別の件数表**
   - 行 = 担当者、列 = 未着手 / 進行中 / 完了 の件数。
   - 担当者は ID（`sato` など）ではなく**名前（佐藤など）**で表示する。

## 非目標

- タスクの作成・編集・削除の変更、スキーマ変更（既存の担当者・状態・期限の項目で足りるため）。
- 通知（メール・チャット）、グラフ、期間指定、担当者・状態での絞り込み。
- 既存の `/tasks` 一覧や API の挙動変更。

## 失敗とみなす状態（アンチゴール）

- 期限超過の情報が、他の情報に埋もれて目立たない。
- 担当者が ID のまま表示される。
- 完了済みのタスクが期限超過に数えられる。

## 定義・振る舞い

- **期限超過** = 状態が `done` 以外 かつ 期限（`dueDate`）が「今日」より前。期限が今日のタスクは超過に含めない。
- **何日過ぎたか** = 今日 − 期限 の日数（期限の翌日なら 1 日）。
- 一覧の並びは、超過日数の多い順（同数なら ID 順）。
- 期限超過が 0 件のときは、0 件であることと「期限超過のタスクはありません」を表示する。
- 件数表は、タスクが 0 件の担当者も行として出す（全ユーザーが対象）。各セルは 0 を表示する。
- 画面の文言はすべて日本語。ログインが必要（未ログインは `/login` へ）。

## 画面の置き場所

- 新規ページ `/dashboard`（ログイン必須）。`/tasks` からリンクで行き来できるようにする。

## 実装上の制約（CLAUDE.md より）

- 集計・絞り込みのロジックは `src/lib/` の関数に置き、ページは表示だけを書く。
- ロジックの追加には `tests/` の単体テストを付ける（期限当日・完了済み・0 件の担当者などの境界を含める）。
- 新しい外部ライブラリは追加しない。変更は上記の範囲にとどめる。
- 「今日」はテストできるよう関数の引数で渡せる形にする（テストでは固定日付を使う）。

## 依頼者に確認せず私が決めたこと（要確認）

- 画面を `/dashboard` の別ページにした（`/tasks` 自体は変更しない）。
- 「今日」の基準はサーバーの日本時間（Asia/Tokyo）の日付とした。
- 期限当日は超過に含めない。
- 超過一覧は超過日数の降順で並べる。
- 件数表に合計行・合計列は付けない（依頼がなかったため）。
