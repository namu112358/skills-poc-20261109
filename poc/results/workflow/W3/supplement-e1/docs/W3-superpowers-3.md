# 要件: チーム進捗の見える化（「進捗」画面）

## 背景と目的

- 毎週月曜朝の定例（15分）で、リーダーが画面を共有してチーム全員で進捗を確認している。
- 今のタスク一覧は全件が並ぶだけで、「誰がどれくらい抱えているか」「どれが遅れているか」がひと目で分からない。現在は各自に口頭で聞いて回っている。
- 目的: **遅れているタスクを早く見つけて、手を打てるようにする。**
- 主な利用者はリーダー。メンバーが見てもよい（ログイン済みの全ユーザーが閲覧できる）。

## 作るもの

新しい画面「進捗」（`/progress`）を追加する。表示は上から次の順にする（依頼者の指定: 遅れているタスクを先に）。

### 1. 遅れているタスク（最優先・いちばん目立たせる）

- 「遅れ」の定義: **期限を過ぎていて、完了していない（未着手・進行中）タスク**。
- 件数を大きく表示する。
- 一覧には、タイトル・担当者（名前）・期限・「何日過ぎたか」を出す。
- 期限切れは赤など強い色で目立たせる。遅れが 0 件のときは、その旨を落ち着いた表示で出す（例:「遅れているタスクはありません」）。

### 2. 担当者ごとの件数

- 表の形にする。行は担当者、列は 未着手 / 進行中 / 完了。
- 担当者は ID（`sato`）ではなく名前（佐藤）で表示する。
- 今週完了した件数を担当者ごとに見られるようにする（表の列として、または別表。置き方は実装側で決めてよい）。

### 3. ヘッダーからの導線

- ヘッダー（`src/app/layout.tsx`）に「進捗」へのリンクを追加する。

## 完了日時の記録（DB の変更あり）

- 「今週完了した数」を数えるために、**ステータスを完了にした日時**を記録する。
- 完了から別のステータスに戻したときは、その記録を消す。
- 過去の分を埋める必要はない（記録を始めてから）。記録が無い完了済みタスクは、今週完了の集計に含めない。
- スキーマは `src/lib/db/migrations.ts` の末尾に新しい番号のマイグレーションを追加して変える（既存のマイグレーションは書き換えない）。
- 記録するのは、画面や API からステータスが完了に変わったとき（タスクの更新、および完了状態での新規作成）。

## やらないこと（範囲外）

- 今のタスク一覧（`/tasks`）の表示と絞り込みは変えない。
- 進捗画面は閲覧専用。タスクの追加・変更はこれまでの画面や API で行う。
- 過去の完了日時の補完、通知、グラフ、期間の切り替え、担当者での絞り込みは今回は作らない。
- 新しい外部ライブラリは追加しない。

## 実装側で決めてよいこと／仮置きの判断

1・2 は依頼者が確認済み。3〜6 は依頼者から「お任せします」と回答があり、下記の判断で進める（実装側で妥当な範囲で調整してよい）。

1. **「今週」**は月曜〜日曜。日付の基準は日本時間（Asia/Tokyo）。【確認済み】
2. **何日過ぎたか**は「今日 − 期限」の日数。期限が今日のタスクは遅れに含めない（期限の翌日から遅れ）。【確認済み】
3. 遅れの一覧は、過ぎた日数が多い順に並べる。同じ日数なら ID 順。
4. 担当者ごとの表には、タスクが 0 件の担当者も含め、全ユーザーを出す。
5. URL は `/progress`。未ログインのときは、他のページと同じくログイン画面へ誘導する。
6. 完了日時はサーバー側で記録する（クライアントからは受け取らない）。すでに完了のタスクを完了のまま更新しても、記録は更新しない。

## 守ること（CLAUDE.md の規約）

- 集計・絞り込みのロジックは `src/lib/` に置き、ページは表示だけにする。画面の文言は日本語。
- SQL はプレースホルダを使う。
- ロジックを追加・変更したら `tests/` に単体テストを追加する（遅れの判定、日数、今週の範囲、完了日時の記録と取り消し、担当者ごとの集計）。
- 完了後、`npm run typecheck` / `npm test` / `npm run build` が通ること。

## 受け入れ条件

- 初期データで `/progress` を開くと、遅れているタスクの件数と一覧が最上部に出る（日付によって 0 件のこともある）。
- 担当者ごとの 未着手・進行中・完了 の件数が、名前付きの表で正しく出る。
- タスクを完了にすると、担当者の「今週完了」が増える。完了から戻すと減る。
- ヘッダーから「進捗」に移動できる。`/tasks` の見た目と絞り込みは従来どおり。
