# 要件: チーム進捗サマリー画面

## 背景と目的

- 依頼者はチームのリーダー。毎週の定例で、各自に口頭で状況を聞いて回っている。
- 現在のタスク一覧は全件が並ぶだけで、「誰がどれくらい抱えているか」「どれが遅れているか」がひと目で分からない。
- 目的: 定例で、遅れているタスクを早く見つけて手を打てるようにする。
- 主な利用者はリーダー。メンバーも閲覧してよい(ログイン済みなら誰でも見られる)。

## やること

新しい画面「進捗サマリー」を追加する。画面の文言は日本語。

1. **期限切れタスクの枠(画面でいちばん目立たせる。表より上に置く)**
   - 「期限を過ぎていて、完了していないタスク」の件数を見出しに出す。
   - タスクの一覧を出す。各行に、タイトル・担当者(名前)・期限・何日過ぎたかを表示する。
   - 該当が 0 件のときは、その旨(例:「期限切れのタスクはありません」)を出す。
2. **担当者別の件数表**
   - 担当者ごとに、未着手・進行中・完了の件数を表で出す。
   - 担当者は ID ではなく名前(佐藤など)で表示する。

## 判定のルール

- 「期限切れ」= 状態が完了ではなく、かつ期限が今日より前。**期限が今日のタスクは期限切れに含めない。**(依頼者の決定)
- 「何日過ぎたか」= 今日 − 期限(日数)。

## やらないこと

- **既存のタスク一覧の表示と絞り込みは変えない。**名前表示は新しい画面だけ。(依頼者の決定)
- スキーマの変更(マイグレーション追加)はしない。既存の `tasks` と `users` で足りる。
- タスクの作成・更新 API の変更、新しい外部ライブラリの追加はしない。
- 通知、グラフ、期間での絞り込み、CSV 出力などは今回は対象外。

## 制約(CLAUDE.md より)

- 集計・絞り込みのロジックは `src/lib/` の関数に置き、ページには表示の処理だけを書く。
- ロジックには `tests/` に単体テストを追加する(期限が今日・昨日・明日、完了済み、タスクが 0 件の担当者などを確認する)。
- ページでは `requireUser()` でログインを確認する。
- SQL はプレースホルダを使う。

## ビルダーに任せる点(依頼者が「お任せ」とした、または未指定の点)

以下はこちらの判断で、依頼者の決定ではない。

- 画面の URL は `/summary`。この画面へのリンクは、全ページ共通のヘッダー(`src/app/layout.tsx`、「タスク一覧」リンクの隣)に置く。(依頼者の決定)`/tasks` のページ本体には手を入れない。
- 「今日」は日本時間(Asia/Tokyo)の日付で判定する。(依頼者の決定)サーバーのタイムゾーンに依存させない。テストできるよう、関数は `today` を引数で受け取る。
- 担当者の表は、タスクが 0 件のユーザーも 0 件として全員出す。並び順はユーザー ID 順。
- 期限切れの並びは、超過日数の多い順(並び順は依頼者からお任せ)。
- 期限切れの枠は、目立つ色(赤系)と大きめの件数表示にする。具体的な見た目は任せる。

## 決まっていない点

- 「遅れ」に、期限前でも着手していないタスクなどを含めるかは未検討。今回は上の「期限切れ」だけを対象にする。
