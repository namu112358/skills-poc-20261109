# 要件: 進捗の見える化

## 背景・目的

リーダーは毎週の定例で、各メンバーに口頭で状況を聞いて回っている。現在のタスク一覧は全件が並ぶだけで、誰がどれくらい抱えているか、どれが遅れているかがひと目で分からない。
**特に、遅れているタスクを早く見つけて手を打てるようにする。**

- 主な利用者: リーダー。メンバーも閲覧してよい。
- 閲覧権限: ログインしている人は全員分を見られる。未ログインには見せない。
- 目標: 2 週間以内に最初の版を使い始める。最低限の内容で始め、足りなければ後で足す。

## スコープ

### 1. 「進捗」画面（新規）

- パスは `/progress`。ヘッダーに「進捗」のリンクを追加する（既存の「タスク一覧」リンクは残す）。
- 未ログインのときは、他のページと同様にログイン画面へ誘導する。
- 数字と表だけで表示する。グラフは使わない。画面の文言は日本語にする。
- 担当者は ID ではなく名前（佐藤など）で表示する。
- 表示する内容は、上から次の順にする。

#### 1-1. 期限超過（最も目立たせる）

- 定義: 期限が今日より前で、ステータスが完了ではないタスク。
- 件数と一覧を表示する。一覧の項目は、タイトル、担当者、期限、超過日数（何日過ぎたか）。
- 並び順は超過日数の多い順（同数ならタスク ID 順）。
- 該当が 0 件のときは、その旨を文言で示す。

#### 1-2. 期限間近

- 定義: 期限が今日を含めて 7 日以内（今日〜今日 + 6 日）で、ステータスが完了ではないタスク。期限超過とは重複させず、別の区画で表示する。
- 件数と一覧（タイトル、担当者、期限、あと何日）を表示する。並び順は期限の近い順。

#### 1-3. 担当者別の件数

- 行は担当者、列は未着手・進行中・完了の件数。合計も出す。タスクが 0 件の担当者も行を出す。
- 件数のセルをクリックすると、その担当者かつそのステータスで絞り込んだタスク一覧（`/tasks`）に移れる。
  - 件数が 0 のセルはリンクにしなくてよい。
- 担当者別の期限超過の件数も、この表で分かるようにする（列を足す）。

#### 1-4. 今週の完了数

- 担当者ごとに、今週（月曜〜日曜）に完了したタスクの数を表示する。
- 全体の完了率（完了件数 ÷ 全件数）を数値で 1 つ表示する（任意項目。依頼者から「お任せ」とされたので採用する）。

### 2. 完了日時の記録（データ変更）

- ステータスを「完了」にした日時を記録する。
  - 作成時から完了のタスクも、その時点で記録する。
  - 完了から別のステータスに戻したら、記録を消す。
  - 完了のまま他の項目（タイトルなど）だけを更新したときは、記録を変えない。
- 過去の分は埋めない。記録を始める前に完了していたタスクは完了日時が空になり、「今週の完了数」には数えない。
- 既存の DB を壊さないよう、`migrations.ts` の末尾に新しい番号のマイグレーションとして追加する。
- 記録は、画面と API のどちらから更新しても同じ規則で行う。更新処理は `src/lib/tasks.ts` の `createTask` / `updateTask` に集約されているので、そこで行う。

### 3. 担当者での絞り込み（`/tasks` への追加）

- `/tasks` に URL パラメータ `assignee` を追加する。値は存在するユーザー ID で検証し、不正な値や存在しない ID は「指定なし」として扱う。
- 既存の表示とステータスの絞り込みは変えない。担当者とステータスは同時に指定できる。
- 絞り込みフォームに担当者の選択肢を追加する。

### 4. API（JSON）

- `GET /api/progress` を追加する（ログイン必須、未ログインは 401）。画面と同じ集計を JSON で返す。
- 既存の `GET /api/tasks` に `assignee` パラメータを追加するかは任せる。追加する場合は不正な値を「指定なし」として扱う。

## 判断した前提

- 「今日」は日本時間（JST, UTC+9）の日付とする。サーバーのタイムゾーンには依存しない。期限は `YYYY-MM-DD` の日付として比較する。
- 期限超過、期限間近（7 日以内）、今週の判定は、すべて JST の日付で行う。
- 今週は月曜始まり、日曜終わりとし、JST で判定する。完了日時は UTC の ISO 8601 で保存し、今週の判定時に JST の日付へ変換する。
- 期限超過の日数は、日付の差で数える（期限が昨日なら 1 日）。
- 集計に必要なのは既存のステータスと期限だけで、メンバーの入力項目は増やさない。
- 現在の時刻・日付を引数で受け取れる形にして、単体テストで日付を固定できるようにする。

## スコープ外

- 通知（メール、Slack など）
- 進捗率（%）、工数、ポイントの入力
- グラフ、ガントチャート、バーンダウンチャート
- 過去からの推移、先週との比較
- 過去の完了日時の補完
- 新しい外部ライブラリの追加
- 既存のタスク一覧の表示変更（担当者の絞り込み追加を除く）

## 受け入れ条件

1. ログイン後、ヘッダーの「進捗」から `/progress` を開ける。未ログインではログイン画面に移る。
2. 期限超過の区画が最上部にあり、定義どおりのタスクだけが、超過日数の多い順に出る。完了済みのタスクや期限が今日のタスクは含まれない。
3. 期限間近の区画に、今日〜今日 + 6 日が期限の未完了タスクだけが出る。期限超過のタスクは出ない。
4. 担当者別の表で、名前と、未着手・進行中・完了の件数が正しく出る。件数をクリックすると、該当の担当者・ステータスで絞り込まれた `/tasks` に移る。
5. 今週完了したタスク数が担当者ごとに正しく出る。先週以前に完了したものと、完了日時が空のものは数えない。
6. ステータスを完了にすると完了日時が記録され、完了から戻すと消える。画面操作でも API でも同じ。
7. `/tasks` に何も指定しないときの表示は、これまでと変わらない。不正な `assignee` やステータスの値は「指定なし」として扱う。
8. `GET /api/progress` は未ログインで 401、ログイン済みで集計結果の JSON を返す。
9. 追加・変更したロジック（期限超過・期限間近・担当者別の件数・今週の完了数・完了日時の記録・担当者の絞り込み）に単体テストがあり、`npm run typecheck`、`npm test`、`npm run build` が通る。

## 実装の方針（概要）

- 集計は `src/lib/progress.ts`（新規）に置き、ページコンポーネントには表示だけを書く。
- SQL の値はプレースホルダで渡す。マイグレーションは新しい番号を末尾に追加する。
- 実装は別の作業で行う。この文書は要件の確定までを扱う。
