# 要件: チームの進捗の可視化（「進捗」画面）

## 背景・目的

- 毎週の定例で、リーダーが各メンバーに口頭で状況を聞いて回っている。
- 「誰がどれくらい抱えているか」「どのタスクが遅れているか」がひと目で分からない。
- リーダーが遅れているタスクを早く見つけ、手を打てるようにする。

## 利用者・権限

- 主な利用者はリーダー。メンバーも見てよい。
- ログインしていれば、誰でも全員分を見られる（役割による出し分けはしない）。
- 未ログインの利用者には見せない（ページはログイン画面へ、API は 401）。

## 用語の定義

- **今日**: 日本時間（JST）の日付。サーバーのタイムゾーンに依存させない。
- **期限切れ**: 期限が今日より前で、ステータスが完了ではないタスク。
- **期限が近い**: 期限が今日〜今日+6日（今日を含めて 7 日以内）で、ステータスが完了ではないタスク。期限切れは含めない。
- **遅れ日数**: 今日 − 期限（日）。
- **今週**: JST の月曜 0:00 から日曜 24:00 まで（月曜始まり。お任せ事項のため、この定義を採用）。
- **今週完了**: 完了日時が今週に入っているタスク。

## 機能要件

### 1. 「進捗」画面（新規ページ。例: `/progress`）

上から次の順に表示する。数字と表だけで構成し、グラフは使わない。

1. **期限切れの未完了タスク**（最も目立たせる）
   - 件数を見出しに表示する。
   - 一覧の列は、タイトル・担当者（名前）・期限・遅れ日数。遅れ日数の多い順に並べる。
   - 0 件のときは「期限切れのタスクはありません」と表示する。
   - 目立たせ方（赤系の強調など）はお任せ。色だけに頼らず、文言でも分かるようにする。
2. **期限が近い未完了タスク**
   - 件数と一覧を、期限切れとは別に表示する。
   - 列は、タイトル・担当者（名前）・期限・あと何日か（今日は「今日」）。期限の近い順に並べる。
3. **担当者ごとの集計表**
   - 行は全ユーザー（担当タスクが 0 件の人も含む）。担当者は名前で表示する。
   - 列は、未着手・進行中・完了の件数、今週完了の件数。参考として期限切れの件数も出す。
   - 未着手・進行中・完了の件数は、クリックすると「その担当者・そのステータスで絞り込んだタスク一覧」へ移る。
   - 0 件のセルはリンクにしない（お任せ事項）。

### 2. ヘッダーからの導線

- ログイン中のヘッダーに「進捗」へのリンクを追加する。

### 3. タスク一覧の変更（最小限）

- 既存の表示・ステータス絞り込みは変えない。
- 担当者での絞り込みを追加する。URL のクエリは `?assignee=<ユーザー ID>`。
  - ステータスと併用できる。
  - 不正な値や存在しない ID は「指定なし」として扱う。
  - 絞り込みフォームに担当者の選択肢を足す。

### 4. 完了日時の記録

- ステータスを「完了」にした日時を記録する（`tasks` に完了日時の列を追加。UTC の ISO 8601）。
- 「完了」から別のステータスに戻したら、記録を消す。
- 作成時にステータスが「完了」だった場合も、その時点の日時を記録する。
- 完了のまま他の項目だけを更新したときは、記録を変えない。
- 過去の分の埋め戻しはしない。既存の完了タスクは完了日時なしとし、今週完了には数えない。

### 5. API

- 画面とは別に、進捗の集計を返す JSON API を追加する（例: `GET /api/progress`）。
  - 要望では「お任せ」。画面と同じ集計関数を使うため、追加の負担は小さい。
  - 未ログインは 401。エラー形式は既存と同じ `{ error, details? }`。

## 非機能要件・制約

- 進捗率（%）、工数、見積もりなどの新しい入力項目は作らない。既存のステータスと期限だけで算出する。
- グラフ、ガントチャート、バーンダウンチャートは作らない。
- 新しい外部ライブラリは追加しない。
- 通知（メール・Slack など）は対象外。
- 過去からの推移（先週との比較など）や、ステータス変更履歴の保存は対象外。
- 画面の文言は日本語にする。
- 集計と絞り込みのロジックは `src/lib/` に置く。ページには表示の処理だけを書く。
- スキーマ変更は `src/lib/db/migrations.ts` の末尾に新しいマイグレーション（version 3）として追加する。既存のマイグレーションは書き換えない。
- SQL はプレースホルダを使う。
- 「今日」と「今週」は関数の引数で基準日時を渡せるようにし、単体テストで固定した日時を使えるようにする。
- ロジックを追加・変更したら `tests/` に単体テストを追加する。
- 初期データ（`seed.ts`）は、デモで見えるように期限切れ・期限間近・今週完了のタスクが出る内容にする（お任せ事項。ただし初期の完了タスクの完了日時は、シードで明示的に設定する）。

## 受け入れ条件（例）

- 基準日が 2026-11-09 のとき、期限 2026-11-05 の未完了タスクが「期限切れ・4 日遅れ」として出る。
- 期限 2026-11-15 の未完了は「期限が近い」、2026-11-16 は出ない。
- 期限が今日のタスクは期限切れではなく「期限が近い（今日）」に出る。
- 完了のタスクは期限が過ぎていても、期限切れ・期限が近いのどちらにも出ない。
- UTC で日付をまたぐ時刻（例: UTC 15:30 は JST では翌日）でも、JST の日付で判定される。
- 完了にすると完了日時が入り、進行中に戻すと消える。
- 集計表の件数をクリックすると、その担当者・ステータスで絞り込まれた一覧が開く。件数と一覧の行数が一致する。
- 未ログインでは進捗画面・API を見られない。

## お任せ事項（依頼者に確認済み）

- 「今週」の起点は月曜とした。
- 担当者別の表に「期限切れ件数」の列を足した。
- JSON API は付ける方針とした。
- 初期データは、期限切れ・期限間近・今週完了が出る内容にする。
