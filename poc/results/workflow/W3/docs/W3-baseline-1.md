# 要件: チーム進捗画面

## 背景と目的

チームの進捗が見えにくい。特に「誰がどれくらい抱えていて、どれが遅れているか」がひと目で分からない。
毎週月曜朝の定例（15分、画面共有）で、リーダーが遅れているタスクをすぐに見つけて手を打てる状態にする。

## 成功の判断基準

定例で「進捗」画面を開くだけで、期限切れの未完了タスクを最初に見つけられ、全員の状況が分かる。

## 利用者と権限

- 主な利用者はリーダー。メンバーも閲覧してよい。
- ログインしているユーザーなら誰でも全員分を見られる。
- 未ログインは見られない。ページは未ログインならログイン画面へ誘導する（既存ページと同じ `requireUser()` の挙動）。

## 機能要件

### F1. 「進捗」画面の新設

- 新しいページ（例: `/progress`）を作る。ヘッダー（`src/app/layout.tsx`）に「進捗」リンクを追加する。
- 既存のタスク一覧（`/tasks`）の表示と絞り込みは変更しない。
- 表示は数字と表のみ。グラフ・ガントチャート・バーンダウンチャートは使わない。

### F2. 期限切れの未完了タスク（最優先・最も目立つ位置に表示）

- 定義: 期限（`dueDate`）が今日（JST）より前で、ステータスが完了以外のタスク。期限が今日のタスクは期限切れに含めない。
- 画面の最上部に、件数と一覧を出す。
- 一覧の列: タスク名、担当者（名前）、期限、期限を何日過ぎたか。
- 並び順: 超過日数の多い順。同じ日数ならタスク ID 順。
- 0 件のときは「期限切れのタスクはありません」と表示する。
- 背景色や太字などで、他のセクションより目立たせる。

### F3. 7日以内に期限が来る未完了タスク

- 定義: 期限が今日（JST）から 6 日後まで（今日を含めて 7 日間）で、ステータスが完了以外のタスク。期限切れは含めない。
- 期限切れとは別のセクションで、件数と一覧（タスク名、担当者、期限、あと何日）を出す。
- 並び順: 期限の早い順。同じ日ならタスク ID 順。

### F4. 担当者別の状況表

- 行は担当者（全ユーザー。タスクが 0 件の人も出す）、表示は名前（佐藤など。ID ではない）。
- 列: 未着手、進行中、完了、今週完了（F5）。合計行は不要。
- 列の数字は件数のみ。進捗率は出さない。

### F5. 今週の完了数

- 担当者ごとに、今週（月曜〜日曜、JST）に完了したタスクの数を F4 の表に出す。
- 完了日時が記録されているタスクだけが対象。

### F6. 完了日時の記録

- ステータスを完了にしたとき、その日時を記録する。
- 完了から他のステータスに戻したら、記録を消す。
- 完了のまま他の項目（タイトル・担当者・期限）だけを変更した場合は、記録を変えない。
- 作成時にステータスが完了なら、作成時刻を記録する。
- 過去分の補完はしない。記録開始前に完了したタスクは、完了日時が空で「今週完了」には数えない（「完了」列の件数には数える）。
- 記録は API（`PATCH /api/tasks/:id`、`POST /api/tasks`）の変更でも画面経由でも、同じ `src/lib/tasks.ts` の関数で行う。

### F7. 日付の判定

- 期限切れ・7日以内・今週の判定は、すべて日本時間（JST）の日付で行う。
- 期限（`YYYY-MM-DD`）は日付のまま比較する。完了日時は UTC の ISO 8601 で保存し、判定時に JST の日付へ変換する。
- 「今日」は関数の引数で渡せるようにして、テストで固定できるようにする。

## 非機能・制約

- 新しい外部ライブラリは追加しない。
- 集計は `src/lib/` の関数に置く。ページには表示の処理だけを書く（`CLAUDE.md` の規約 1）。
- スキーマ変更は `src/lib/db/migrations.ts` の末尾にバージョン 3 を追加する。`tasks` に完了日時の列（NULL 可）を追加する。既存のマイグレーションは書き換えない。
- SQL はプレースホルダを使う。画面の文言は日本語。
- ロジックの追加・変更には `tests/` に単体テストを追加する。特に、日付の境界（期限が今日、6 日後、7 日後、月曜 0 時と日曜 24 時の前後、UTC と JST の日付がずれる時間帯）と、完了日時の付け外しをテストする。
- 既存の API のレスポンス形式は変えない。完了日時を API の応答に出すかは実装時に決める（出さなくてよい）。

## スコープ外

- メール・Slack などの通知
- グラフ、ガントチャート、バーンダウンチャート
- 過去からの推移、先週との比較
- 進捗率、工数の入力
- 過去分の完了日時の補完
- 既存のタスク一覧の表示・絞り込みの変更

## 前提・仮置き（依頼者の回答にない点。実装時に変更してよい）

- 画面のパスは `/progress`、ヘッダーのリンク名は「進捗」。
- 担当者の表示名は `users.name` を使う。
- 「今週完了」の列は F4 の表に含める（担当者ごとに見る要望を、同じ表にまとめた）。
- 期限切れ・7日以内の一覧の並び順は上記のとおり。
- 画面は定例で共有するため、自動更新は不要（開くたびに最新を表示する）。

## 確認方法（受け入れ条件）

1. 未ログインで進捗画面を開くとログイン画面へ移る。
2. ログイン後、ヘッダーから進捗画面へ行ける。`/tasks` の表示と絞り込みは従来どおり。
3. 期限切れの未完了タスクが最上部に出て、超過日数が正しい。完了済みのタスクは出ない。
4. 7日以内の未完了タスクが、期限切れとは別に出る。
5. 担当者別の表の件数が、タスクの実データと一致する。
6. タスクを完了にすると完了日時が記録され、今週分なら「今週完了」に反映される。完了から戻すと記録が消える。
7. `npm run typecheck`、`npm test`、`npm run build` が通る。
