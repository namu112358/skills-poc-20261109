# 要件: 「進捗」画面（チームの進捗を見えるようにする）

状態: 要件確定（実装前）。次は `ce-plan` で実装計画を立てる。
このドキュメントは「何を作るか」だけを定める。実装方法（関数の置き場所、SQL、コンポーネント構成など）は計画で決める。

## 背景と目的

- 利用場面: 開発チーム（佐藤・鈴木・田中の 3 人）が、毎週月曜朝の定例（15 分）で画面を共有して全員で見る。
- 現状の悩み: 今は各自に口頭で状況を聞いて回っている。タスク一覧は全件が並ぶだけで、誰がどれくらい抱えているか、どれが遅れているかがひと目で分からない。
- 主な利用者: リーダーの佐藤。遅れているタスクを早く見つけて手を打つ。メンバーが見るのもかまわない（ログインしていれば誰でも見られる）。
- 成功の状態: 定例で口頭の聞き取りをしなくても、「画面を開く → 遅れと負荷を確認する → 気になる件数から該当タスクへ移る」で状況が把握できる。

## スコープ

### 作るもの

1. 新しい専用画面「進捗」（遅れ一覧・遅れそう一覧・担当者別の件数表）
2. ヘッダーに「進捗」へのリンク
3. タスク一覧（`/tasks`）に担当者での絞り込みを追加

### 作らないもの（対象外）

- 「進行中のまま長く動いていない」タスクの検出（変更履歴の保存が必要になるため要らない）
- 遅れ・遅れそうの判定に使う項目の追加（既存のステータスと期限だけで判定する）
- 担当者別の表に「遅れ」の列を設けること（遅れは専用の一覧で見る）
- ログイン直後の遷移先の変更（今までどおり `/tasks`）
- 今のタスク一覧の表示内容・ステータス絞り込みの変更

## 要件

### R1. 画面とナビゲーション

- R1-1. 新しい画面「進捗」を追加する。ログインが必要で、未ログインのときは他の画面と同じくログイン画面へ誘導する。
- R1-2. ヘッダー（ログイン中に表示される既存のヘッダー）に「進捗」へのリンクを置き、「タスク一覧」と行き来できる。
- R1-3. 画面の文言はすべて日本語にする。

### R2. 遅れ（いちばん目立たせる）

- R2-1. 「遅れ」とは、期限が今日より前で、ステータスが完了ではないタスク。
- R2-2. 画面の最上部に、遅れの**件数**と**一覧**を、他の項目より目立つ形で表示する。
- R2-3. 一覧の各行に、タスク名、担当者（名前）、期限、期限から何日過ぎたかを表示する。タスク名からタスクの詳細画面へ移れる。
- R2-4. 並び順は、過ぎた日数が多いものを上にする。
- R2-5. 遅れが 0 件のときは、その旨を示す文言を表示する（例:「遅れているタスクはありません。」）。

### R3. 遅れそう

- R3-1. 「遅れそう」とは、期限が今日を含めて 7 日以内（今日〜6 日後）で、ステータスが完了ではないタスク。ステータスが未着手に限らず、進行中も含む。
- R3-2. 遅れ（R2）とは別の区画に表示する。同じタスクが遅れと遅れそうの両方に出ない（期限切れは遅れだけ）。
- R3-3. 各行に、タスク名、担当者（名前）、期限、期限まであと何日か（今日が期限なら「今日」）を表示する。並び順は期限が近いものを上にする。
- R3-4. 0 件のときは、その旨を示す文言を表示する。

### R4. 担当者別の件数表

- R4-1. 担当者ごとに、未着手・進行中・完了の件数を表で表示する。
- R4-2. 担当者は ID ではなく名前（佐藤・鈴木・田中）で表示する。
- R4-3. 件数のセルをクリックすると、その担当者・そのステータスで絞り込んだタスク一覧（`/tasks`）へ移る。件数が 0 のセルも同様に移れる（移った先は「該当するタスクはありません。」になる）。
- R4-4. 表に出る担当者は、登録されているすべてのユーザー。担当タスクが 0 件の人も行を表示する。

### R5. タスク一覧の担当者絞り込み

- R5-1. タスク一覧に、担当者での絞り込みを追加する。「すべて」と各担当者（名前）から選べる。
- R5-2. 担当者の絞り込みは、既存のステータス絞り込みと組み合わせて使える。
- R5-3. URL のクエリで指定された担当者が存在しない、または不正な値のときは「指定なし」として扱う（ステータスの絞り込みと同じ扱い）。
- R5-4. 担当者の絞り込みを指定しない場合の表示・ステータス絞り込みの動作は、今までと変わらない。

## 受け入れ例

初期データ（今日 = 2026-11-09 として）の場合:

- 遅れ: 期限が 11/09 より前で未完了のものは、現状の初期データには無い（「要件定義書のレビュー」「リリースノート作成」は完了のため対象外）。遅れが 0 件のときの文言が出る。
- 遅れそう: 11/09〜11/15 に期限が来る未完了は「ログイン画面のデザイン」（11/12・進行中）と「API 設計」（11/14・進行中）。遅れそうの区画に出る。
- 担当者別の表: 佐藤は未着手 1・進行中 1・完了 1、鈴木は未着手 1・進行中 1・完了 0、田中は未着手 1・進行中 0・完了 1。
- 表の「佐藤・進行中」の件数をクリックすると、担当者 = 佐藤、ステータス = 進行中で絞り込まれた一覧に移り、「API 設計」だけが表示される。
- 期限が 11/05 のまま未完了のタスクがあれば、「遅れ」に「4 日超過」のように表示される。

## 前提とした事項（依頼者に確認できていないもの）

- 「今日」の基準はチームの現地の暦日（日本時間）とする。タイムゾーンの扱いは計画で具体化する。
- 遅れ・遅れそうは全担当者のタスクを対象とし、ログインユーザー自身の担当に限らない。
- 画面の見た目の細かい作り（色、レイアウト）は指定が無い。既存画面と同程度の素朴なスタイルを基本とし、「遅れ」が最も目立つこと（R2-2）だけを必須とする。
- 担当者の表示名は、既存のユーザーの名前（`users.name`）を使う。

## 計画への引き継ぎ

- 既存規約（`CLAUDE.md`）に従う: データの取得・集計は `src/lib/` に置く、クエリパラメータは型ガードで検証する、ロジックの追加には `tests/` の単体テストを付ける、新しい外部ライブラリは追加しない。
- スキーマの変更は不要の見込み（既存の `tasks.status` / `due_date` / `assignee` と `users.name` で足りる）。
- 日数の計算を含む判定は、「今日」を引数で渡せる形にしてテストできるようにすること（計画で設計する）。
