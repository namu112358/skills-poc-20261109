# 要件: チームの進捗ダッシュボード

## 背景・目的
- 毎週の定例で、メンバー一人ひとりに口頭で状況を聞いて回っている。
- 現状のタスク一覧は全件が並ぶだけで、「誰がどれくらい抱えているか」「どれが遅れているか」がひと目で分からない。
- 目的: 画面を見れば進捗が分かる状態にし、定例で状況を聞いて回る手間を減らす。

## 用語
- **遅れているタスク**: 期限（`due_date`）を過ぎていて、状態が「完了」でないタスク。
  - 依頼者の確認済み。期限前に長く動いていないタスクは対象外。
- **今週**: 月曜〜日曜。日本時間（JST）で数える。
- **今日**: 日本時間（JST）の日付。

## ゴール
1. メンバーごとに、担当タスク数を状態別（未着手 / 進行中 / 完了）に表示する。
2. メンバーごとに、遅れているタスクの件数を表示する。
3. 遅れているタスクの一覧（タイトル・担当者・期限）を表示する。期限が古いものが上に来る。
4. メンバーごとに、今週に完了したタスクの数を表示する。
5. ログイン済みのメンバーなら、全員分を閲覧できる。未ログインの人には見せない（ページはログイン画面へ誘導する）。
6. 新しく「進捗」画面を作り、ヘッダーから行けるようにする。既存のタスク一覧の表示・絞り込みは変えない。

## 完了日時の記録（スキーマ変更あり）
- タスクの状態を「完了」にした日時を記録する。
- 「完了」から別の状態に戻したら、その記録は消す。
- 記録を始める前に完了していたタスクは、過去分を埋めない（完了日時なし）。今週の完了数には数えない。
- 状態の更新は `PATCH /api/tasks/:id` を通る。更新の経路が他にもある場合は、同じ記録の処理を通す。

## ノンゴール（今回やらないこと）
- 期限前の停滞（長く更新がないタスク）の検出
- 通知（メール・チャット等）、週次レポートの自動送信
- グラフ・履歴・推移の表示
- 過去に完了したタスクの完了日時の埋め戻し
- 新しい外部ライブラリの追加
- 既存のタスク一覧の表示・絞り込みの変更

## 失敗とみなす状態（アンチゴール）
- 画面を見ても、結局メンバーに口頭で聞かないと状況が分からない。
- 遅れ判定が実態とずれる（例: 完了済みを遅れに数える、当日期限を遅れに数える）。
- 今週の完了数がずれる（例: 完了から戻したタスクを数える、週の境界が UTC のまま）。
- 未ログインの人に進捗が見える。

## 制約（既存の規約）
- 画面の文言は日本語。
- データの取得・集計は `src/lib/` の関数に置き、ページには表示の処理だけを書く。
- ロジックを追加・変更したら `tests/` に単体テストを追加する。
- SQL はプレースホルダを使う。
- スキーマ変更は `src/lib/db/migrations.ts` の末尾に新しい番号のマイグレーションを追加する。既存のマイグレーションは書き換えない。

## 実装方針（Claude の判断。依頼者の合意ではない）
- 新しいページ（例: `/progress`、表示名は「進捗」）として追加し、ヘッダーにリンクを置く。ページは `requireUser()` でログインを確認する。
- `tasks` に完了日時の列（例: `completed_at`、ISO 8601 UTC、NULL 可）を足す。
- 完了日時の設定・消去は `src/lib/` の状態更新の関数で行い、API Route には書かない。状態が「完了」になった時に設定し、「完了」から戻した時に消す。すでに完了のタスクを再度完了に更新しても日時は上書きしない。
- 期限の判定は「期限日 < 今日」とし、当日はまだ遅れていない扱いにする。期限は日付（YYYY-MM-DD）の文字列で比較する。
- 今週の範囲は、JST の月曜 0:00 以上、次の月曜 0:00 未満とする。UTC で保存した日時と比べられるよう、境界を変換する。
- 「今日」と現在時刻は引数で渡せるようにして、テストしやすくする。
- 画面の細かいレイアウトは実装者に任せる。

## 未確認事項
- 特になし。閲覧者（ログイン済みなら全員）、「今日」の基準（JST）、完了日時の扱いは依頼者に確認済み。
