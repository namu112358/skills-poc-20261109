# 要件: チーム進捗ダッシュボード

## 背景と目的

- 依頼者: 佐藤さん（チームのリーダー）。
- 困りごと: 毎週の定例で、鈴木さん・田中さんに口頭で状況を聞いて回っている。現在のタスク一覧は全件が並ぶだけで、「誰がどれくらい抱えているか」「どれが遅れているか」がひと目で分からない。
- 目的: 定例で「遅れているタスクを早く見つけて手を打つ」。
- 成功の姿: 定例でダッシュボードを開けば、口頭で聞いて回らなくても、遅れているタスクと担当者ごとの状況が分かる。

## 利用場面

- 毎週月曜の朝、15分の定例。画面を共有し、全員で見る。
- 主な利用者は佐藤さん。メンバーが見ても構わない（ログインしていれば全員が閲覧可）。

## 用語

- **遅れているタスク（期限切れ）**: 期限を過ぎていて、まだ完了していないタスク。状態が `done` 以外で、期限が今日より前のもの。（依頼者が確認済み）

## 機能要件

### F1. ダッシュボード画面（新規）

担当者ごとの集計と、期限切れの一覧を1つの画面に表示する。画面の文言は日本語にする。

**F1-1. 期限切れの件数と一覧（画面でいちばん目立たせる）** — 依頼者の指定

- 期限切れの件数を大きく表示する。
- 期限切れタスクの一覧を、件数の下に表示する。
- 一覧の各行に、担当者（名前）・期限・何日過ぎたかを出す。タスクのタイトルも出す（私の判断）。
- 期限切れが0件のときは、その旨が分かる表示にする（私の判断）。

**F1-2. 担当者ごとの件数表** — 依頼者の指定

- 担当者ごとに、未着手（`todo`）・進行中（`in_progress`）・完了（`done`）の件数を表で見られるようにする。
- 担当者はIDではなく名前（佐藤など）で表示する。

### F2. 既存のタスク一覧は変更しない — 依頼者の指定

- 現在のタスク一覧の表示と絞り込みは、変えない。

## 決定事項と私の判断

依頼者は、以下の項目（日付はJSTで判定、並び順、全ユーザー表示、文字の大きさ）を「その案で進めてよい」と確認済みです。入口の項目（2）は依頼者の指定に合わせて直しました。残りは私の判断です。

1. 画面の場所は新しい URL `/dashboard` とする。ログインが必要で、未ログインならログイン画面へ送る（既存ページと同じ扱い）。
2. 画面名は「進捗」とする。入口は、ログイン中に表示される既存のヘッダー（`src/app/layout.tsx`。「タスク一覧」リンクの隣）にリンクを足す形にする。タスク一覧のページ本体（`src/app/tasks/`）にはリンクを足さず、手も入れない。（依頼者が指定）
3. 「何日過ぎたか」は、日本時間（JST）の今日の日付から期限の日付までの日数で数える。期限当日は期限切れとしない。翌日に「1日超過」になる。（JST は依頼者が確認済み）
4. 期限切れ一覧は、超過日数が多い順に並べる。同じ日数なら、タスクの番号順にする。
5. 件数表には全ユーザー（佐藤・鈴木・田中）を載せる。タスクが0件のユーザーも、行を0件で表示する。
6. 集計の対象は全タスクとする。期間での絞り込みや、担当者での絞り込みはしない。
7. 画面共有で見やすいよう、文字を大きめにする。細かなデザインは、実装する側に任せる。

## 非目標（今回はやらない）

- 通知、メール送信、グラフ、履歴の記録。
- 既存のタスク一覧の変更。
- タスクのデータ項目の追加（現在の担当者・期限・状態で足りる。DBのスキーマ変更は不要）。
- 期限切れの定義の変更（「期限を過ぎ、未完了」以外の見方）。

## 制約（リポジトリの規約）

- 新しい外部ライブラリは追加しない。
- データの取得と集計は `src/lib/` の関数に置き、ページには表示の処理だけを書く。
- 「今日の日付」は関数の引数で受け取れるようにして、単体テストで日付を固定できるようにする。
- SQL の値はプレースホルダで渡す。
- ロジックを追加したら、`tests/` に単体テストを追加する。
- 変更は依頼された範囲にとどめる。

## 受け入れ基準

0. ヘッダーに「進捗」リンクがあり、`/dashboard` に移れる。タスク一覧のページ本体（`src/app/tasks/`）は変更しない。
1. `/dashboard` を開くと、期限切れの件数と一覧が最上部に目立つ形で出る。
2. 一覧の各行に、担当者の名前・期限・超過日数が出る。完了済みのタスクと、期限が今日以降のタスクは含まれない。
3. 担当者ごとの未着手・進行中・完了の件数が表に出て、担当者は名前で表示される。
4. 既存の `/tasks` の表示と絞り込みは、これまでと同じ動きをする。
5. `npm run typecheck` と `npm test` が通る。集計と期限切れ判定（当日・前日・完了済み・0件）に単体テストがある。
