# W20（E2）レビューの組み合わせの評価 — 結果レポート

- 実施: 2026-11-10。設計: [`poc/tasks/wf-W20-design.md`](../../../tasks/wf-W20-design.md)。判断の記録: [`decisions.md`](decisions.md)。
- 評価セット: PoC の試行で確かめた不具合を「障害」として集めた 5 題材（作り物 1・実際の試行 3・不具合なし 1）。
- 本数: 35 本。1 回目は 5 設定 × 5 題材。2 回目は high 系（`/code-review high`・組み合わせ）だけ。使用量の上限が近いとのユーザーの指示で縮めた。

## 結論

- **実際の不具合を一番よく見つけたのは `/review-pr` と Superpowers（`requesting-code-review`）。** 実際の 3 題材の正解 9 件のうち、どちらも 8 件を見つけた。誤った指摘は 0 件。費用は 1 回 $0.7 ほど。
- **`/code-review high` は、作り物（W9）では満点だが、実際の題材では弱い。** 実際の 3 題材では 9 件中 1〜3 件で、2 回とも要件の抜け・違反（G1・G2・C3 の B1〜B4）をほとんど拾わなかった。安い（$0.43）代わりに、PR の説明の要件と照らし合わせる見方が薄い。
- **組み合わせ（high + `/review-pr`）は、`/review-pr` 単独より増えなかった。** 費用は 1.7 倍（$1.21）で、C5 の細かい指摘が最も多い（19 件）。
- **全設定が見落とした不具合がある。** W19 superpowers 1 の「本番で詳細の画面が 500」（C2 の B1）は、35 本のどれも見つけなかった。テスト・型検査・ビルドは通り、本番の起動でだけ落ちる種類の不具合は、差分を読むレビューでは拾えない。起動して確かめる検証（E2E・本番ビルドでの画面の確認）が要る。
- **判定役の判定は安定していた。** 2 回判定した 9 件は、正解との一致がすべて同じだった（一致率 1.0）。

## 開発フローへの反映（提案）

| 段 | 今の早見表 | 提案 |
|---|---|---|
| PR のレビュー（normal） | 意図のレビュー + `/review-pr code tests errors` | そのまま。E2 で最もよく見つけた |
| セルフレビュー（normal） | Superpowers `requesting-code-review` | そのまま。`/review-pr` と同じくらい見つけた |
| セルフレビュー（normal・hard） | `/code-review high --fix` | 要件の抜けに弱いので、これだけに頼らない。意図のレビュー（受入条件と照らす）と組で使う |
| hard の上乗せ | `/code-review max` | E2 では測っていない。high と同じ弱みがあるかを次に確かめる |
| 検証 | テスト・ビルド・lint | **本番の起動で画面を開く確認を足す**（C2 の B1 はレビューでは誰も拾えなかった） |

## 制約

- 1 回目は 1 回ずつ。2 回目は high 系だけ。low・`/review-pr`・Superpowers の揺れは測っていない。
- 使用量の上限で 19 本が何もできずに終わり、リセットの後に流し直した（判断の記録）。
- 判定役が「判断できない（unsure）」「正解外だが本当らしい（real）」とした指摘は、担当が読んで決める予定だったが、使用量を抑えるため今回は読んでいない。誤った指摘の数には入れていない。
- 通るまでの往復の回数は測っていない（代理人の判断 E-D7）。
